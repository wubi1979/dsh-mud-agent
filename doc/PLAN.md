- 索引：本计划与 T20（匹配编译入口单点化、暂延后）同域但不同问题，合并与否见 6.1。

### 1.2 目标

1. 一条命令的**终结形态、结果分类与预算**，全系统**只登记一处**，工具面与流程面消费同一份。
2. 判断结果（"哪一种结局"）成为**可复用的数据**，而不是各消费者自行解读原文行。
3. 表**覆盖全部命令**、每条**显式声明收窗条件**；未登记命令**不收窗、只等超时**（fail-loud，不猜）。增长轴是**命令数**（有限），不是"命令 × 前置条件"的叉积。

### 1.3 非目标

- 不建"命令类型"维度，不给 `mud_send` 加 `type: user|pass|cmd`（见 DEC-9）。
- 不把**隐式**静默当收窗（**声明的、且经插话滤波的**静默是收窗条件之一，见 DEC-3 / DEC-14）。
- 本计划不表达"证据式 / 行为性"分类（`mud_walk` 的 `unaccepted` / `hard-stop` 留调用侧，见 DEC-10）。
- 不改 locked 流程（`login` / `fullme`）的既有判据——显式声明优先（见 DEC-4）。

## 第 2 章 背景与核心决策

### 2.1 现状：同一判据写在三处，流程面拿不到

| # | 落点 | 形式 | 消费者 |
|---|---|---|---|
| ① | `mud-core3/src/tools.ts` `LONG_CMD_PROFILES`（§8.7） | 命令头 → `until` / `failOn` / `timeoutMs` | `mud_send` |
| ② | 同文件 `WALK_UNTIL` / `WALK_FAILON` / `WALK_QUIET_MS`（§8.7） | 同形，写死为常量 | `mud_walk` |
| ③ | 流程 `wait` 步内联（§8.10；`flows/login.ts`、`flows/fullme.ts`） | 同一批句子的独立副本 | 流程解释器 |

数据流是**两条平行的读窗路径**：工具面在 `tools.ts` 查表后 `rt.read`；流程面 `service.ts` 的 `workflowIoFor` 只做 `io.read: (opts, initial) => rt.read(opts, initial ?? [])`，**从不查表**。

### 2.2 已发生的正确性洞（非风格问题）

v0.0.68 把 dz / sleep 的"受理被拒"句补进了 ①，而流程走 ③：流程里的 `dz` 声明不到这句 ⇒ 被拒时**判据全不命中，窗口空等到 120s，以 `timeout` 出口（`ok:false`）收束**；同一时刻工具面能拿到 `failOn` 分类并把拒绝句原文回给 agent。同一命令两副面孔，是 §0.2 规则 4「同一事实只写一处」被打破的直接后果。

### 2.3 曾担心的失控，与本计划为何判断可控

- **失控的论证（用户提出，成立）**：`bai` 拜师也会因道德 / 天赋不够失败——**失败前置条件与命令正交**。按命令建表 = 把"命令 × 前置条件"的叉积当表存，键选错则表必然长满。
- **可控的论证（本计划的前提）**：
  1. **成本被"声明粒度"压住**（DEC-3 / DEC-6）：多数命令的收窗条件是"边界"（即时命令 GA 1:1），由 A.2 的**一条共享事实**支撑，**不需要逐条语料**；真正需要逐条 A.6 实录的只有"边界不可作终局"的那一小族（长程 / 多步 / 无 GA 命令）。
  2. **不收窗就不猜**（DEC-4）：未登记命令不再退到隐式缺省，而是**只等超时**并把原因点名——缺口由 fail-loud 暴露，不会静默给出错误答案。半吊子条目比不登记更毒（成功路径会挂到 timeout），故"不登记 + 吵"优于"登记不全 + 静默"。
  3. 全局表的收益正是需求本身：**任意地方使用了该命令，都获得一致且准确的判断**。

### 2.4 决策表

| 编号 | 决策 | 理由 / 证据 |
|---|---|---|
| **DEC-1** | 表落 **core3 数据面**（`packages/mud-core3/src/command-profiles.ts`），纯层零宿主 import；`mud-workflow` 契约层只装类型与端口，**不装数据** | §8.8 纯度裁定（该包"纯架构不含数据"）；流程侧经 `workflowIoFor` 缝消费 |
| **DEC-2** | 表条目 = **判据 + 预算 + 结果分类**，不含分支与处置 | 工具面无分支（决策归 agent，§7.6）；流程面无模型在环。混入决策则工具面无法消费 |
| **DEC-3** | 条目的**收窗条件必须显式声明**（DEC-4），以**判定器选择**表达形态：`closeOn` 为**单值封闭四枚举**——`'ga'`（GA / EOR 收窗，判据仅分类）、`'criteria'`（文本判据收窗，GA 不武装）、`'race'`（判据与静默竞速，先到者收窗）、`'quiet'`（纯静默收窗）。**无缺省、无组合自由度**——四种配方各自封闭；代码面由四个具名判定器工厂声明，与数据面同构（DEC-15） | 回填 `walk` 时曾暴露"单值枚举装不下"（它同时用 until / failOn 与 quietMs 1500，§8.7），随后收敛：实际存在的配方只有四种，"机制数组"的 2³ 组合是**假空间**（用户裁定 2026-10-11「判定器即形态」）；`bai`=`'ga'`、`dz`=`'criteria'`、`walk`=`'race'`、LM=`'quiet'`。竞速时沿用现役判定序 `failOn > until > gaCount > maxLines`，异步 quiet 与之赛跑，命中帧 `by` 指出实际收窗者 |
| **DEC-4** | **取消"缺省收窗"**：收窗只能来自**表条目**或**调用点显式声明**；两者都没有 ⇒ **只等超时**（`reason:'timeout'`，文案点名"该命令未登记收窗"并给出声明示例）。**不再有 `gaCount: 1` 隐式兜底** | "未命中 ⇒ 退缺省"对未入表的长程命令是**错误缺省**（受理帧 GA 即收，与 v0.0.66 根因同型，见 2.2）。把"猜"删掉，缺口由 fail-loud 暴露——与 §8.13「结构缺出口 ⇒ 结构化 timeout 点名」同型纪律。**修订（2026-10-11）：翻转分两步**——表骨架与回填先行（翻转前未登记命令暂按 `gaCount: 1` 边界收窗；**兜底作为基线参与槽级合并**——可被调用点 `closeOn` 覆盖，不在合并后强加），**T26.7 以 T26.1 覆盖审计通过为门**再切换点名超时（避免确认词 / 频道 / 社交 emote 等日常高频未登记命令成片挂起的阵痛期）；**空命令特例**：`sent === ''` 不是"需要登记的命令"，显式归 `'ga'`（A.2 1:1 事实直接覆盖，§8.7 现口径不变） |
| **DEC-5** | 收窗配方的来源与合成（用户裁定 2026-10-11：**槽级合并**）：**表条目为基线，调用点声明逐槽合并——同名槽（`outcomes`）与同名字段（`closeOn` / `quietMs` / `timeoutMs`）都是后声明为准**，未声明的一律继承表条目；无表条目时调用点声明即全部配方，且 `closeOn` 必须显式（否则按未登记收窗处理）。静默**可以是**收窗条件（`closeOn: 'quiet'`，用户举例：LM 命令——既无完成判据也无 GA），但**必须与插话滤波绑定**（DEC-14），否则就违反它自己不免疫插话的事实。收窗条件强度分三级：**判据**（可证明结局）/ **边界**（协议证明，但归属不可证）/ **静默**（推定，"认为结束"） | GA 是"服务器推完一批并要求继续"的协议事件，**不与某条命令绑定**；静默既不免疫插话又依赖服务端节奏。两者都只有在被**明确声明**时才有确定含义（"插话是否带 GA"见 6.2 第 5 项）。强度分级决定消费侧如何对待：`silence` 收窗**只能产生条目预置的推定槽**（如 `推定完成`，`patterns: []`），不能凭空产生判据式结局。**合并优于整体覆盖**：整体覆盖会连带丢掉表条目的 fail 槽（被拒句不可命中 ⇒ 空等，dz 洞的微缩版）；合并让"任意地方使用该命令都获得一致且准确的判断"（2.3 目标）在调用点也成立 |
| **DEC-6** | **表覆盖全部命令**（79 条清单，见 6.1 第 7 项）：`'ga'` 类条目由 A.2 的**一条共享事实**（即时命令 GA 1:1）支撑，**不需要逐条语料**；`'criteria'` / `'race'` / `'quiet'` 类条目必须逐条 A.6 语料 | 收窗条件显式化之后，"表完备"是系统可用的前提；其成本因"边界类共用一条事实"而可控——需要逐条实测的只有长程 / 多步那一小族 |
| **DEC-7** | 结局**槽位模型**（用户提案 2026-10-10）：契约层枚举 `OutcomeName` 定义**全集**；**每个命令条目写全所有槽**（类型系统强制，缺键即编译期红），未支持的槽显式取**空值** `null`（不是字段缺失）；条目支持某结局 ⇔ 该槽已填。**流程引用空槽 ⇒ 报错**；引用枚举外的名字 ⇒ 报错；槽集不全 ⇒ 表侧自检 fail-loud。**枚举只增不删**（同 §0.2「章节号永不复用」精神） | 早稿把"该命令不产生这个结局"列为**静态不可判**（要 core3 表、契约层看不见）——槽位模型把它变成**可静态表示的事实**：空槽是条目自己声明出来的。枚举新增成员 = 所有条目的槽集合自动扩展且仍为空 ⇒ **纯加性**，不动任何条目；用户那句"枚举中类型的值均为空"正是这一点。**修订（2026-10-11，随判定器形态）**：槽表由"每条目写全全集"放宽为**判定器内 `Partial`**（缺席 = 该命令不支持此结局）——新增枚举成员后所有条目默认不支持它，纯加性行为不变，只是少了"逐条补 null"的编译噪音；带牙齿的三项保留：**流程引用缺席槽 ⇒ 报错**、装配期自检 fail-loud、枚举只增不删 |
| **DEC-8** | 匹配对象 = **实际发送的最终字符串**，在**缝侧**匹配；族用正则表达；查询类用条目谓词排除；**未命中 = 不套用表**（收窗须由调用点声明，DEC-4） | 流程命令带槽替换（`{target}`），必须替换后匹配；族边界由语料决定；`walk -c` / `-q` 答复与未受理行同族，注入判据会误判（§8.7 原文） |

| **DEC-10** | 表只提供**判据式**分类；**证据式**（`walk` 的 `unaccepted` = 无正向证据）与**行为性**（`hard-stop` = 同位置软阻断连击 ≥ 2）分类留调用侧 | §8.7 / 附录 A.9：用户 2026-10-08 裁定不用单行"拒绝行文"判据；两者都不是文本判据 |
| **DEC-11** | 与 tracker 规则表**不强行合并**；共用 A.6 语料登记，同句重复时按规则 id 引用 | 键与用途不同（"命令 → 结局" vs "原文 → 语义分区"）；先例：§8.7 读后投影由 `DEFAULT_TRACK_RULES` 推导 |
| **DEC-12** | 未知命令的"收窗模式"**本计划不做** | 已被 DEC-4 覆盖：未登记 = 无收窗 = 超时点名；调用点随时可显式声明（`listen.gaCount: 1` / `listen.until`），无需新模式词汇 |
| **DEC-13** | **流程侧静态门取"告警"**（用户拍板 2026-10-10）：步 `action.send` 的**命令头是字面量**、既命不中表、又未声明收窗 ⇒ 保存门**放行 + 告警**（不拒存）；**命令头不是字面量**（头部为槽替换 / 凭据命令）⇒ 只能**运行时**判。告警须**可读可见**：`save` 返回 `{ok:true, warnings:[…]}` 由工具面渲染给模型，并 host warn 点名 | 不阻断 §8.11 的「粗胚 → 执行 → 结构化失败 → 修缮 → 重试」闭环——拒存会让粗胚根本存不下来。但**"引用枚举外 / 引用空槽"仍走报错档**（口径见 3.5：前者是 schema 层天然拒存，后者运行期 fail-loud） |

## 第 3 章 机制与契约

### 3.1 条目契约（草案）：`defineCommand` 数据单元 + 四个判定器

**判定器即形态**（DEC-3 / DEC-15）：条目不声明"收窗机制组合"，而是选择一个**具名判定器**；判定器是**纯数据工厂**（返回可序列化的形态声明），不是行为。执行不进条目——只有一条路径（`resolveAwaitPlan` → ReadMachine）。

```ts
// ── commands/define.ts：契约与判定器（core3 数据面；类型是词汇表不是数据）──

/** 结局槽：判据句内联（DEC-20 撤销后的口径），A.6 语料为准。 */
interface OutcomeSlot { kind: 'ok' | 'fail'; patterns: readonly string[] }
/** 槽表（DEC-7 修订）：Partial——缺席 = 该命令不支持此结局；流程引用缺席槽 ⇒ 报错。 */
type SlotTable = Partial<Record<OutcomeName, OutcomeSlot>>

/**
 * 判定器返回的数据形态 = `closeOn` 四值封闭枚举（契约层词汇，可序列化；
 * 调用点 wait / listen 直接声明同一形状——同一形态两处使用，3.10）。
 */
type Judge =
  | { closeOn: 'ga' }                                            // byBoundary：GA 收窗，槽仅分类
  | { closeOn: 'criteria'; outcomes: SlotTable }                 // byOutcomes：判据收窗，GA 不武装
  | { closeOn: 'race'; quietMs: number; outcomes: SlotTable }    // byQuiet：判据与静默竞速
  | { closeOn: 'quiet'; quietMs: number }                        // bySilence：纯静默

declare const byBoundary: (outcomes: SlotTable) => Judge
declare const byOutcomes: (outcomes: SlotTable) => Judge
declare const byQuiet:  (quietMs: number, outcomes: SlotTable) => Judge
declare const bySilence: (quietMs: number, outcomes?: SlotTable) => Judge  // 缺省槽 = 推定完成（patterns: []，机制填）

/** 命令单元：数据，不含行为。 */
function defineCommand(c: {
  id: string                   // 规范命令头 = 表键（'dazuo'）；缝侧按首词精确命中，match 由 id/aliases 派生
  aliases?: readonly string[]  // 族（'dz'；xue/learn/practice 共条目）
  exempt?: RegExp              // 查询/豁免子形态（如 walk -c/-q）：命中即不套用本条目（§8.7）
  timeoutMs: number            // 预算法定值（系统注入；豁免模型面 60s 钳制，§8.7）
  maxLines?: number            // 行数兜底；缺省不设（剪断会误判）
  resolve: Judge               // 形态声明 = 判定器选择
  meta: { corpus: string }     // 语料出处（A.6 纪律）：ga 类可引 A.2 共享事实；其余逐条指附录 A
}): CommandProfile
```

实现要点：

- **装配**：`command-profiles.ts` 退为**装配器**——收集五个分组文件导出的构建期数组 → 把 `Judge` 编译为"正则数组 + 并行名表"（GA 仍是 `ReadOpts.gaCount`，`'ga'` ⇒ 1）→ 装配期自检 → 导出只读总表。**读窗机匹配模型零变化**（仍是 §5.2 / §8.13 的单点整窗 `exec`）。
- **文件组织**（用户裁定 2026-10-11）：`packages/mud-core3/src/commands/` 下 `define.ts`（契约 + 四判定器 + 类型）+ **五个分组文件** `std.ts` / `skill.ts` / `usr.ts` / `stunt.ts` / `profession.ts`（按游戏命令族划分；成员归属以 79 清单实录为准，T26.1 覆盖审计时定稿）。
- **校验两层**：工厂签名编译期挡（`byOutcomes` 缺 `outcomes`、`byQuiet`/`bySilence` 缺 `quietMs` 等签名不合即红）；装配期自检 fail-loud（枚举外名字、槽值非法、id / aliases 与他条目冲突——同 `tools.ts` "注册完整性自检"纪律）。
- **构建期数组，无运行期注册面**（DEC-18 补充）：条目 = 各文件 `defineCommand({...})` 数组元素，agent 不可写。
- 判据句**内联**在判定器槽里；同句跨条目复现时就地提常量（DEC-20 撤销后的口径）。

### 3.2 收窗形态的语义（四值配方，各自封闭）

- `'ga'`：**GA / EOR 收窗**；已填槽只用于给结果分类（命中即带 `outcome` 名；未命中则收窗、**无结局**、**不记失配 error**）。`bai` 属此类。
- `'criteria'`：**文本判据收窗，GA 不武装**（`dz` 受理帧的 GA 正是要忽略的那个）；判据失配按 §5.2 记 error（既有纪律）。
- `'race'`：**判据与静默竞速**，谁先到谁收窗，命中帧 `by` 如实报告；`walk` 的 `arrived` / `soft-stop` / `incomplete` 正是这样分的（§8.7）。
- `'quiet'`：**滤波后的静默收窗**（滤波后置期间按现役"任何行都重置"语义——DEC-14 修订；本期用例只有 `walk` 的竞速与 LM 的纯静默）。收束以**命中帧 `by: 'silence'`** 上报（`outcome` 取条目声明的推定名，如"推定完成"），消费侧据此按**正常完成**处理，而不是走旧的"非 done ⇒ timeout 出口"路径（§8.13 的"quiet 一律走 timeout 出口"**仅对未声明的 quiet 继续成立**）。静默是推定、不证明结局 ⇒ 只产生条目预置的推定槽（DEC-5 强度分级）。**`'quiet'` 下所有槽仅分类**（静默是唯一收窗者，与 `'ga'` 的"判据仅分类"同构；槽级合并进来的槽同此）——想要句子参与收窗 ⇒ 显式 `'race'`。
- **无声明**（表未命中且调用点未声明）：**不收窗，只等超时**（DEC-4）；`maxLines` 仅作兜底并如实报告 `reason`，不冒充完成。

### 3.3 具名分类与命中帧

命中帧由 `{ by, index, groups }` 扩展为 `{ by, index, groups, outcome?: OutcomeName }`。名字是**对外契约**：流程按名路由、工具面按名渲染、观测按名归因。`by` 报告**实际收窗者**（`'ga'` / `'criteria'` / `'silence'` / `'maxLines'`），`index` 保留为该槽 `patterns` 数组内下标；内部仍是编译后的正则数组（见 3.1）。

**枚举的位置**：**结局枚举**（`OutcomeName`）与**形态枚举**（`closeOn` 的四值）都定义在契约层（`mud-workflow/contract` 的词汇表单点）——它们是**词汇表不是数据**，故不违反 §8.8；core3 的判定器只能把正则挂到枚举成员上（DEC-7 / DEC-15）。

### 3.4 匹配与优先级

- 匹配在**缝侧**对最终字符串进行；命令头 + 词边界；族用正则一条覆盖（如 `/^(xue|learn|practice)(\s|$)/`）。
- 查询类排除写在条目 `exempt`（不另立概念）；`walk -c` / `-q` 不注入判据、不参与"在出发点"判定（§8.7 现有口径）。
- 优先级与合成（DEC-4 / DEC-5）：**表条目为基线，调用点声明槽级合并、同名后声明为准**；**两者都无 ⇒ 不收窗，只等超时**，结果文案点名"该命令未登记收窗"并给出声明示例（`closeOn` + `outcomes`）。**不存在"现状缺省"这一档。**（翻转分两步，见 DEC-4 修订与 T26.7；空命令特例归 `'ga'`。）
- **解析单点（DEC-21）**：工具面与流程缝共用同一纯函数 `resolveAwaitPlan(sent, callerDecl) → AwaitPlan`（表条目为基线 + 调用点槽级合并；特例：`sent === ''` 与凭据命令不走表）。行为一致性由构造保证，该函数是本计划测试密度的第一落点。
- **超时点名兼作语料工单（DEC-22）**：点名文案同时输出维护者面信息——实际发送串、本窗行数摘要、建议条目骨架（`match` 正则初稿）；点名即工单，缺口从"发现"直连"登记 A.x + 补条目"。

### 3.5 流程侧：具名路由与静态校验边界

- **路由（DEC-19）**：步的 `onOutcome`（**单张表**，槽名 → 目标）按命中槽名路由；**取消** `branch` / `onFailOn`（下标式）。存量流程读时归一（合成槽名 + 告警），见 3.10。
- **三层报错（DEC-7；用户要的"引用空则报错"）**：
  1. **引用枚举外的名字**（拼写 / 未定义）⇒ **保存门拒存**。纯静态——枚举在契约层，是词汇表不是游戏事实（§8.8 不破）。
  2. **引用枚举内、但该命令的槽缺席** ⇒ 报错。判定需要"命令 → 槽填充情况"（core3 表，契约层看不见），两条落点：**运行期必做**——引擎解析条目时校验步骤引用的槽，fail-loud 点名（步骤 + 槽 + 命令），这也是含槽替换的**动态命令**唯一能走的一档；**保存期**由 core3 经可选端口 `slotsOf(cmd)` 注入保存门（契约层只声明端口类型，不装数据），见 6.1 第 5 项。
  3. **槽值非法 / 形态参数不合** ⇒ **装配期 fail-loud**（表侧自检；工厂签名已编译期挡大部分——DEC-7 修订后槽表为 Partial，"槽集不全"不再是一类错误）。
- `onOutcome` 未覆盖、但**已定义且该命令支持**的槽 ⇒ 走 `next`（与 `branch` 越界同义）。
- **连带（捕获槽，已由 DEC-19 定案）**：`checkFlow` 原规定捕获组只允许出现在 `until[0]`（§8.13），而槽表**没有"第 0 条"的位置语义** ⇒ 改为**具名** `wait.captureFrom: '<槽名>'`，捕获组数只对该槽计；`login` / `fullme` 随词汇收敛一并改写（3.10）。

**动态命令穷举（保存期不可判的情形，用户问 2026-10-10）**

| 情形 | 例 | 保存期可判？ | 处置 |
|---|---|---|---|
| 命令头字面 + 参数含槽 | `xue {skill}` / `bai {master}` | **可判**（按命令头查表） | 静态门正常生效——**这不属于动态命令** |
| 命令头整段来自槽 | `{cmd} {arg}` | 否 | 运行期：缝侧拿**最终字符串**查表（DEC-8）；未声明收窗 ⇒ 超时点名（DEC-4） |
| **凭据命令** | `sendCredential: '{name}'` / `'{pass}'`（`login` 步 1–2） | 否（头部就是账号数据） | 运行期；且凭据命令**不入表**（账号数据不是游戏命令），流程必须显式声明收窗——`login` 步 1–7 正是这么写的 |
| **工具面直接发送** | `mud_send` 的 `cmd`；`mud_walk` 内部拼装的 `walk …` / `set walk_speed …` | 无保存门 | 运行期（DEC-4 超时点名 + 声明指引） |
| **玩家 / 服务器别名** | 发出的字符串不是真实命令头 | 否 | 同上（未命中表 ⇒ 不收窗 ⇒ 超时点名） |

**运行期这一档有两项职责**：① 未声明收窗 ⇒ 超时点名（DEC-4）；② 流程引用的槽在该命令条目上为 `null` ⇒ **fail-loud**（DEC-7 第 2 档）。

### 3.6 缝侧"本窗等的是哪条命令"

`workflowIoFor` 的 `io.send` / `io.sendCredential` 记 `lastSent`（最终字符串），`io.read` 在步未显式声明判据时按它查表注入。依据：会话级持有者独占（§8.6）⇒ 窗口内无第二执行体发送，该推断在结构上成立。**必须**同时输出归因字段（`command` / `outcome` / `source`），否则 action-at-a-distance 无法排查。

### 3.8 示例条目（形态示例；**落地前必须补实录**）

按 A.6 纪律，下列原文位为占位，**不得凭印象写正则**：

```ts
// commands/std.ts —— 拜师（即时命令）：GA 收窗，槽仅分类
defineCommand({
  id: 'bai', timeoutMs: 15_000, meta: { corpus: 'A.x（待补）' },
  resolve: byBoundary({
    拜师成功: { kind: 'ok',   patterns: [/* 待实录 */] },
    前置不足: { kind: 'fail', patterns: [/* 道德不够 / 天赋不够 等，同一槽逐条累加 */] },
  }),
})

// commands/skill.ts —— 打坐（长程命令）：判据收窗，GA 不武装
defineCommand({
  id: 'dazuo', aliases: ['dz'], timeoutMs: 120_000, meta: { corpus: 'A.3（2026-10-10）' },
  resolve: byOutcomes({
    完成:     { kind: 'ok',   patterns: [/* A.3 原文 */] },
    突破:     { kind: 'ok',   patterns: [/* A.3 原文 */] },
    内息不足: { kind: 'fail', patterns: [/* 6.2 第 1 项实录后定 */] },
    精神不足: { kind: 'fail', patterns: [/* 同上 */] },
  }),
})

// —— 无判据无 GA 的命令（用户举例 LM）：纯静默，patterns 由机制填
defineCommand({
  id: 'lm', timeoutMs: 60_000, meta: { corpus: 'A.x（待补，6.2 第 7 项）' },

```

`前置不足` 槽名是否跨命令复用由实录与"流程真的需要分支什么"决定（DEC-17）；同句跨条目复现时就地提常量，不为共享立设计（DEC-20 撤销后的口径）。

### 3.9 行为变更与兼容（**破坏性**）

- **未登记命令**：从"`gaCount: 1` 立即收窗"变为"**不收窗 → 超时**"。这是**故意**的破坏性变更（DEC-4）：把"猜"换成"吵"。缓解三条：① 表覆盖 79 条命令（DEC-6）；② 工具描述与 persona 教"未登记命令请显式声明收窗"——`listen.gaCount: 1` 就是原行为；③ 超时文案点名原因与声明示例，agent 可当场自愈并把声明沉淀进流程（§8.11 进化闭环）。
- **存量流程**：显式判据的步零变化；未声明判据、依赖隐式缺省的步在新规则下会超时 ⇒ 由 DEC-13 静态门在**保存期**暴露。
- **裸读（无 `cmd`）不受影响**：它不是"某条命令的收窗"，仍按 `quietMs + maxLines` 走（§8.7 现有口径）。
- **静默路径的行为变更**：本期重置语义**不变**（现役"任何行都重置"保持，DEC-14 滤波后置随 LM 实录片）；行为变更仅两处——只有 `closeOn` 为 `'race'` / `'quiet'` 时静默才作为收窗者（否则仅兜底），以及静默收窗以 `by: 'silence'` 上报、消费侧走正常出口。存量调用点逐个归类：裸读的 `quietMs: 300` 不受影响（它不是"某条命令的收窗"）；`mud_walk` 的 `1500` 升为条目的 `'race'` 形态（`byQuiet`，行走是多步执行器，静默本就是它的主判据之一，附录 A.9 结论 1）——它也是 T26.4 静默机制的现成消费者。插话滤波落地后 `quietMs` 才改为只由非插话行重置。
- **`maxLines`**：保留为兜底并如实报告收束原因，不冒充完成。

### 3.10 调用点词汇收敛（DEC-19：branch 具名）

**同一形状两处使用**：表条目与调用点 `wait` 共用"结局槽"形状。

```ts
// 调用点 wait：与表条目同字段（closeOn 显式单值——判定器的数据面，3.1）
wait: {
  closeOn: 'criteria',           // 形态显式，不靠字段存在性推定（6.1 第 10 项）
  outcomes: {
    需替换:   { kind: 'ok',   patterns: [REPLACE_SRC] },
    登录成功: { kind: 'ok',   patterns: [SUCCESS_SRC] },
    密码错误: { kind: 'fail', patterns: [BAD_PASS_SRC] },
  },
  captureFrom: 'captchaUrl',   // 具名捕获槽（取代 until[0] 的位置语义）
  flags: 'm',
  timeoutMs: 30_000,
}

// 路由：单张表，kind 决定分流（不再有 branch / onFailOn）
{ onOutcome: {
    需替换:   { goto: 'replace' },
    登录成功: { goto: 'send-empty' },
    密码错误: { exit: { stage: 'bad-pass', ok: false } },
} }
```

- **语义保持**：`kind: 'ok'` 槽命中但未覆盖 ⇒ 走 `next`；`kind: 'fail'` 槽命中但未覆盖 ⇒ **结构化 timeout 出口**（不静默走正常路径，同现役 `onFailOn` 缺省）；一条槽都没命中（GA / `maxLines` 关窗）⇒ 走 `next`；无 `next` 且无覆盖 ⇒ 结构缺出口 timeout 点名。
- **判定序不变**：`kind: 'fail'` 先于 `kind: 'ok'`（对应现役 `failOn > until`，§5.2）。
- **槽级合并（DEC-5，用户裁定 2026-10-11）**：表条目为基线，调用点 `outcomes` 逐槽合并——**同名槽以后声明为准**（该槽 `kind` + `patterns` 整体替换），未声明槽**继承表条目**（fail 槽不因覆盖丢失，dz 洞无微缩版）；`closeOn` / `quietMs` / `timeoutMs` 同为后声明为准。无表条目时调用点声明即全部配方，`closeOn` 必须显式。**"收窄窗"（屏蔽某槽）无语法**：需要时回表改，或届时例证驱动再加。
- **`checkFlow` 新增静态校验**：`onOutcome` 的键必须 ⊆ **合并后的可命中槽集**（该步 `wait.outcomes` ∪ 表条目已填槽；字面量命令保存期经 `slotsOf` 端口可判——6.1 第 5 项，动态命令运行期判，3.5 第 2 档）；`captureFrom` 必须是合并集中已声明的槽；捕获组数只对该槽计（取代 `until[0]` 计组）。
- **读时归一（存量流程）**：旧 `until` / `failOn`（数组）+ `branch` / `onFailOn`（下标）在装载时转换为**合成槽名**（如 `槽1`…）的槽表 + `onOutcome`，并**告警**提示改写为语义槽名；转换保行为不变（§8.11 词汇表演进纪律：不因演进读不出旧记录）。
- **locked 流程改写**：`login` / `fullme` 的表改为具名槽（`login`：`需替换` / `登录成功` / `密码错误` / `需建新人物`；`fullme`：`URL` / `答对` / `答错` / `失效`），同步 `flows/*.md` 声明与 §8.15 / §8.17 的步表。
