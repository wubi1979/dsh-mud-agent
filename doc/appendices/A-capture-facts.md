# 附录 A：抓包与语料事实

> **性质**：**实测事实**（E3 级证据，定义见附录 B）。MUD 侧（pkuxkx）实录，不随宿主换代失效；用于登录流程判据定稿（§8.15）、读窗口参数（§5.2）与语料校准（§13.4）。

## A.1 登录提示行原文（实录）

| 环节 | 原文 |
|---|---|
| 用户名提示（长形态，**判据唯一形态**） | `您的英文名字（要注册新人物请输入new。）：` |
| 用户名提示（短形态，**已不作判据**） | `您的英文名字：` |
| 密码提示（**判据唯一形态**） | `此ID档案已存在，请输入密码：` |
| 同名在线确认 | `您要将另一个连线中的相同人物赶出去，取而代之吗？(y/n)` |
| 用户名不存在（need-new，**用户名动态内嵌**） | `同意玩家须知并使用<用户名>创造一个新的人物，您确定吗(yes)？` |
| 用户名非法 | `对不起，你的英文名字只能用小写英文字母。` |
| 登录完成 | `目前权限：(player)` |
| 断线重连完成 | `重新连线完毕` |

**三条对判据的硬约束（§8.15 实测勘误）**

1. **同名在线确认句不含「同名 / 覆盖 / 替换」等关键词**（实录 2026-09-11）——按关键词集匹配必然漏匹配，必须**按原句匹配**。
2. **「欢迎来到」不可作成功句**：与建连横幅「欢迎来到北大侠客行」**撞车**，登录前即到达会误判成功；成功句只认 `目前权限：(player)` 与 `重新连线完毕`。
3. **提示判据收窄为单形态 + `^` 行首锚（`flags: 'm'`）**（实机 2026-10-03）：短形态 `您的英文名字：`、裸 `请输入密码：` 不再作判据（防聊天语句误触发）；need-new 句**内嵌动态用户名** ⇒ 判据用 `使用\S+创造` 桥接，`(yes)` 括号须转义；整窗按行 join 匹配，`^` 配 `'m'` 才是行首（无 `'m'` = 窗首，提示行在横幅后永不命中）。

## A.2 GA 节拍

- **GA 与命令 1:1**（实测 21/21）。
- **GA 延迟 1–602ms**，远小于投递静默窗口（`deliverQuietMs` 缺省 500ms 量级与 2s 级静默窗）——**GA 是可靠命令边界**（§3.4、§5.2 `gaCount` 判据依据）。
- 结论：`mud_send` 有 `cmd` 时的缺省判据 `gaCount: 1 + maxLines` 兜底因此成立（§8.7）。

## A.3 长程命令

- 例：`dz` —— 受理帧 GA + prompt 之后，**56 批 / 约 57s 无 GA 无 prompt**，完成句与末条推送**同块**到达。
- 受理/完成句原句（用户供给 2026-10-10；§8.7 长程判据预设引用据此）：
  - `dz`（打坐）：受理 = `你盘膝坐下，默运***，一股内息自丹田引出……`（`***` = 所运内功名，动态）；完成 = `你将运转于全身经脉间的内息收回丹田，深深吸了口气，站了起来。`（完成双形态，2026-10-10 用户补：`你的内力增加了！！` 也是完成句——内力上限突破时刻；收尾变体 `你运功完毕，深深吸了口气，站了起来。` 同为完成，2026-10-10 用户补）；**受理被拒** = `你的精神不足，无法控制内息的流动`（2026-10-10 用户补 ⇒ §8.7 failOn，命中即收窗不空等到 timeout）
  - `sleep`（睡觉）：受理 = `你往床上一躺，开始睡觉。`；完成 = `你一觉醒来，精神抖擞地活动了几下手脚。`；**受理被拒** = `你刚刚睡过一觉, 多睡对身体有害无益! `（2026-10-10 用户补 ⇒ §8.7 failOn；原句尾随一个空格，判据取句体不含尾随空白——子串匹配带不带尾随空格都命中）
  - `xue`（学习）：**即时完成、GA 收尾**——非长程，走缺省 `gaCount:1` 即可。
- 空命令事实（2026-10-10 实机观察 agent 误用）：空输入也是命令 ⇒ 同样回 prompt+GA（A.2 1:1 推论）——「发空命令等长程命令完成」只会收在空命令自己的 GA 上，永远等不到完成句；治理 = 长程判据预设 + persona 等待纪律（§8.7），空命令本身曾设可读拒绝、后放开（2026-10-10 二次裁定：根因已除，拒绝不再必要）。
- 结论：
  - **不能只靠 GA 判长命令结束**（`maxLines` 兜底与 `timeoutMs` 必须存在，§8.7）；
  - 长输出的**边界只能靠静默窗口**切分（§4.3 批次粒度与 TCP 块边界无关）。

## A.4 分页

- 每页**独立命令 + 独立 GA**；页尾是换行行 `== 未完继续 88% ==`，**不是 prompt**。
- 结论：分页判据不能依赖 prompt；翻页命令的归属与直发豁免属后置项（§17.3）。

## A.5 服务器不回显

- **服务器不回显命令**（含密码）——密码明文的泄漏面**只在本机**：画面回显、日志、上下文。
- 结论：这正是 §12.2 三道闸必须存在的理由（本地三条路径全封）；画面回显前缀（§5.3）只对**我方发送**打标。

4. **`内力` / `精力` 可超过 `最大内力` / `最大精力`，百分比上限 = 200%**（用户确认 2026-10-06：上限 200%，平时一般不会打坐到 200%）。同刻实录即有对照：`324,648`（=100% / 200%）、`311,622`（=100% / 200%）。"内力充足"一类判据按 `内力 / 最大内力` 的**百分比**取阈，`最大值` 不是 100%。

**校准结论**：
1. **节标题在方括号内且词内带空格**（`[装  备]`）——节标题提取须先取方括号内容剥空白，否则提不到（旧 `≥2` 连串判据只对 `[ 基本功夫 ]` 类凑效）；`[饰  品]` 边框行内还有装饰文（`□腰挂一个锦囊□`），方括号优先同时堵掉该误提。
2. **汇总行**：`你共携带八件器物，负重约二十七斤，接近一成。` → `inventory.件数`（中文数字原文，PLAN 未决 3）、`负重`（`约二十七斤` 原文）、`负重比`（`接近一成` 原文，句尾锚定）。
3. **装备/饰品行**：槽位标签 `[帽子]` 成对左右两列镜像，物品在标签相邻段（左列物品在标签**前**、右列在标签**后**，如 `青色道袍 (+2) [衣服]` / `[鞋子] 麻鞋`）；`--` 与画框字符 = 空槽不写。饰品满布局实录未取得（`[项链]珍珠` 为推断兼容，待实录）。同名牌槽位（护肩×2/护腿×2/戒指×2）按映射键合并**后写覆盖**（已知限制）。
4. **其它行**：`中文名(英文id)` 对、一行可多件、可多行 → `inventory.其它 = [{name,id},…]`（跨行追加）。
5. **写入时机**：分区行跨行合并，块收口（`└`）统一写（同 exp 对照行积攒模式）。
6. **声明序门控**：`i` 规则先于 `skills` 声明，物品行与技能行同为 `中文(id)` 形态 ⇒ 装备/饰品/其它解析**按 section 门控**（技能表 section 为 `基本功夫` 等，永不误抢）。

写入映射见 [tracker.ts](../../packages/mud-core3/src/tracker.ts) `inventoryRow`/`iSlotRow`/`iOtherItems`；判据覆盖：`inventory.{件数,负重,负重比,财物,装备,饰品,其它}`。

### A.8.2 校准结论（七条）

1. **自动攻击是 base 行为**：整场未发任何出招命令，服务器自行结算每拍攻防。⇒ 命令的用途是**干预**，不是驱动。
2. **干预占用一拍**（用户确认 2026-10-06：战斗中吃药占一回合）⇒ 模型为「**每拍一个动作槽**，缺省动作 = 自动攻击，干预 = 占用该槽」。
3. **气血三元组语义**：L2 = `气血上限`（**基准上限，不变**）/ `最大气血`（**生效上限，被 `wound` 削减**）/ `气血`（**当前值，被 `damage` 削减**）。戳行的两个百分比 = `floor(当前/最大)` 与 `floor(最大/基准)`——逐拍对上：
   - `313,283,281` ↔ `99%/90%`（281/283、283/313）· `313,253,187` ↔ `73%/80%` · `313,193,27` ↔ `13%/61%`
   - 实测序列：上限恒定 `313`；最大 `283→253→223→193`（4 次 `wound:+30`）；当前 `281→-1`（11 条受击戳，共 -282）；敌方单次伤害恒 `+32`。
   - ⇒ **创伤（wound）压缩容量，伤害（damage）消耗缓冲**，两者独立。
4. **`hpbrief` 由服务端推送**（用户确认 2026-10-06）：本场它与受击戳**同时出现**，未受击的拍两者都没有 ⇒ 状态**随受伤拍到达**。**待确认**：未受伤的拍服务端是否也推（决定遭遇状态是否需要行文兜底）。
5. **危险有两维**：① `当前/最大`（**缓冲**：低了立刻危险）；② `最大/基准`（**容量**：低了持续作战能力差，必须提前撤）。本场死亡时容量已降到 `193/313 = 61%`。
6. **药只恢复上限、不回当前气血，且占一回合**（用户确认）⇒ 药的定位是**治伤（恢复容量）**，不是急救（回缓冲）。
7. **逃 = `halt` + `move`**（无专用逃跑指令，用户确认）⇒ 逃至少两拍，且**依赖退路（房间出口）数据**。

其余观测：真气 `0`、内力 `325`、精力 `311` **全程满**（基础攻击零消耗，未发绝招/未加力）；食物饮水几乎不动（`384→383`）；`战意` 恒 `80` 而 `气势` 独立累积（`4%→8%→12%→16%`）⇒ **`战意` ≠ `气势`**（A.7 结论 2 的"静气 ≡ 战意"指的是 hp 表的 `【静气】`，与本场的 `气势` 不是同一事实）；经验/潜能本场未变（无击杀）；我方精神 `257/257` 未受击。

## A.9 walk 命令实录（2026-10-08，T23 mud_walk 判据出处；`help walk` + 荆州府路线表 + `walk -c` + 实机行走三行文）

**路线表**（荆州府出发点房间内 `walk` 无参，框线表）：

```
┌───荆州府─────────────┬────────────┬─────┐
│目的地                                │拼音名称                │步数      │
├───────────────────┼────────────┼─────┤
│汉口镇  ◇ 汉水西岸                   │hankou                  │14        │
│鸡鸣渡  ◇ 鸡鸣渡西                   │jiming                  │7         │
│荆山  ◇ 南漳县                       │jingshan                │9         │
│襄阳  ◇ 城中心                       │xiangyang               │15        │
│岳阳  ◇ 陵矶                         │yueyang                 │11        │
├───────────────────┴────────────┼─────┤
│walk [拼音名]命令使用内建路径。                                             │
```

**`help walk` 原文**（要点）：

- `walk [拼音名]`：在有**出发点标记**的房间内使用内建路径行走到其他区域；
- `walk -c`：查询当前区域内建路径出发点（实录答：`当前区域的系统内建路径出发点在：城中心、北渡口…当前区域共有6处内建玩家路径起点，分别在襄阳当铺、半山坡、蒙古营门、雪峰脚下、雪峰脚下、城中心`）；`walk -c [拼音名]`：返回具体地点的路径；
- `walk -p`：行走中途停下（**频繁使用可能会影响任务奖励**）；`walk`（无参）：恢复中途停下的行走；
- `walk -q [区域]`：查询当前区域到其他区域的路径（如 `walk -q 扬州`）；
- `node` 命令：列出玩家自建路径；
- 变量 `walk_speed`：-1 奔跑无延迟 / 0·1 正常（**0.2 秒/步**）/ 2 慢行（0.5s）/ 3 缓步（0.8s）；变量 `walk_path`：自定义路径，格式 `"east|southeast|enter|do_push door"`，必须标准路径（`e` ≠ `east`，非方向用 `do_`）。

**校准结论（T23 判据依据）**：

1. **到达判据 = 行走静默窗**：行走是多步连续输出（步间隔 ≤ 0.8s），每步都出提示符 ⇒ **不能用 gaCount**（第一步就关窗）；静默 1.5s 收束（§8.7 mud_walk 判据预设）。到达/受阻/受理三类**行文已于 2026-10-08 实机取得**（见结论 5）；首版仍以静默窗为唯一判据，行文判据预设列入 T23.5。
2. 超时下限 30s：最长内建路线 15 步 × 慢速档 0.8s ≈ 12s+，留缓冲。
3. `-p` 频繁使用影响任务奖励 ⇒ 工具描述明示慎用；中断恢复 = 无参 `walk`。
4. **出发确认行**（2026-10-08 实机补录）：`walk xiangyang` ⇒ `你决定开始前往襄阳方向走去……`（单行确认，行走随后开始）。可用于区分"已受理"与"未受理"（非出发点房间的拒绝行文仍待实录）。
5. **行走四行文（2026-10-08 实机全程，T23.5/T23.8 判据出处）**：
   - **出发受理**：`你决定开始前往…方向走去……`（承接结论 4）；
   - **到达**：`你到达了荆州府。` ⇒ 作为 `until`（**主判据**，完整句已确证，判据 `^你到达了`）；
   - **受阻停下（软阻断）**：`你因为种种原因停了下来，可以用walk继续进行。` ⇒ 作为 `failOn`（分类出口；**无参 `walk` 可继续**，与结论 3 的"中断恢复"一致）；
   - **未受理（不在出发点标记房间）**：两行连出——
     ```
     当前区域的系统内建路径出发点在：中央广场、土地庙，请查询localmaps获得具体方位。
     当前区域共有5处内建玩家路径起点，分别在当铺、中央广场、客店、土地庙、醉仙楼二楼。
     ```
     判据 `^当前区域的系统内建路径出发点在：`（与 `-c` 查询**同族输出**，见上）；副产品：它同时给出**当前位置所在区域**的出发点列表 ⇒ 位置感知（T23.6）可用。
   - **仍缺**：**硬性阻断**行文（须特殊手段通过，继续 walk 无效）、**精力不足以行动**的行文。**中断后 `walk` 能否继续**：软阻断确认可继续；**遇敌中断按用户裁定（2026-10-08）先假设可恢复**（战斗结束后无参 `walk`），实测发现不能恢复再改口径（T23.7）。

7. **`set walk_speed <值>` = 环境变量设置**（用户确认 2026-10-08）：`-1` 奔跑 / `0`·`1` 正常（0.2s/步）/ `2` 慢行（0.5s）/ `3` 缓步（0.8s，见上）；属**设置类**，归导航服务。**`walk_path`（自定义路径）暂不使用**——用户裁定后期再扩展。
8. **`node get <名称>` = 路径详情（2026-10-08 实机）**：

   ```
   > node get kd_wd
   kd_wd路径由dtp定义
   长版本：west,south,walk xinyang,walk xiangyang,walk wudang,westup,northup,northup,northup,west,northup,northup,eastup,eastup,northup,northup
   短版本：w,s,walk xinyang,walk xiangyang,walk wudang,wu,#3 nu,w,#2 nu,#2 eu,#2 nu
   ```

   - 长版本 = **方向步 + 内嵌 `walk` 调用的序列**（逗号分隔）；短版本 = 方向缩写 + `#N` 重复计数（`wu` = westup、`nu` = northup、`eu` = eastup…）；
   - **`node` 家族的行文与 `walk` 同族**（用户确认 2026-10-08：**node 就是"零散方向步 + `walk`"**）⇒ `failOn`（软阻断 / 未受理）可复用 walk 判据；
   - **但末段可能是方向步**（本实录末段是 `northup`）⇒ **`until` 不能只押 `你到达了`**；`node` 家族收束**主判 = 静默窗**（`quietMs: 1500`），中途若出现 `你到达了…`（内嵌 walk 段）**不应当作终点** ⇒ `node` 的 `until` 不设该句。
   - **直通车判定不需要解析步序列**：`node` 表的「目的地」列（如 `襄阳的城中心`）即可回答"本房间有无直达目标的路径"；`node get` 用于详情 / 诊断。

11. **walk 节点 vs 非 walk 节点：命令语义与专有行文（2026-10-08 实机）**：

    | 场景 | 命令 | 实录返回 |
    |---|---|---|
    | **非 walk 节点** | `walk -c` | 与"未受理"同族两行（`当前区域的系统内建路径出发点在：城中心、北渡口，请查询localmaps获得具体方位。` + `当前区域共有6处内建玩家路径起点，分别在…`） |
    | **非 walk 节点** | `walk`（无参） | **`你现在无法恢复使用内建路径。`** |
    | **walk 节点** | `walk -c` **或** `walk`（无参） | **同源**：都返回路径列表（表头 = 区域名，与无参 `walk` 同一张表） |
    | **walk 节点** | `walk -c <拼音名>` | 具体路径：`信阳 长版本：west,west,west,west,northwest,west,west,west,west,west` / `短版本：#4 w,nw,#5 w` |

    - **"不在出发点"的判定用反证（用户裁定 2026-10-08）**：看本次调用有没有**正向证据**——表类（无参 `walk` / `-c`）**出路径表**、行走类（`walk <拼音名>` / `-p`）**出受理行**（`你决定开始前往…`）⇒ 在出发点；**正向证据缺失即不在出发点**。上面那句 `你现在无法恢复使用内建路径。` 作为**实录留存，但不用作单行判据**（上下文相关的事实靠单行判据脆弱，且那句与 `-c` 的答复同族，容易误判）。`-q`（区域链）与 `-c <拼音名>`（方向序列）的输出与出发点无关 ⇒ **不参与判定**。
    - **路径列表与 `walk -c` 在 walk 节点同源** ⇒ 无参 `walk` 与 `-c` 都可作为"本区域边表"的来源（T23.10b 的记录入口两者都吃）。
    - **`walk -c <拼音名>` = 区域内的方向序列**（长版本 = 完整方向；短版本 = 缩写 + `#N` 重复计数）⇒ 这是**可执行**的"最后一程"（与 `-q` 的"区域名链只有参考意义"形成对照）。判据：`^(?<to>.+?)\s+长版本：(?<long>.+)$` 与 `短版本：(?<short>.+)$`；缩写展开（`#4 w` = `west`×4、`nw` = `northwest`）见 T23.10b 纯层 `expandShortPath`。
