# 附录 B：审计规约（可执行检查表）

- **性质**：**方法规约**——只约束"怎么审"，**不改设计**、不承载设计事实。与 §1–§17 各章节并列使用。
- **适用**：`packages/mud-core3/`、`packages/mud-workflow/` 下全部产物（`src/`、`test/`、`tsconfig*`、`package.json`、`cordis.patch.yml`）。
- **本规约自身的编号（0./1./C1–C7…）独立于设计 `§N`**，不得混写：引用设计一律写**现役 `§N`**；引用归档写 `v1 §N` / `v2 §N`（§0.6）。

## 0. 证据分级（决定一条意见能不能提交）

| 级别 | 定义 | 处置 |
|---|---|---|
| **E1 静态事实** | 源码/配置可直接引用（带 `文件:行`） | 可提交为问题 |
| **E2 设计违背** | E1 + 设计章节的明确条款（带**现役** `§号`） | 可提交为问题 |
| **E3 实测事实** | 本机可执行命令的输出（typecheck / 测试 / 一次真实连接） | 可提交为问题 |
| **E4 推测** | 无 E1 支撑，仅"可能/大概" | **不许提交为问题**，只能作为"质疑"列出 |

**硬规则**

1. **无证据不提交**：任何结论必须能给出 `文件:行`、`§` 或命令输出三者之一；
2. **不确知"不存在"**：判定"某文件/某字段/某分支不存在"前必须**先枚举**（glob/grep 全量），不得凭印象；
3. **路径类结论必须逐级写出解析**（`a/b → .. → ..`），不得靠格式判断；
4. **不把缓存产物当证据**（如 `node_modules/.vite/**/results.json`、旧的 `lib/` 产物），运行结论一律**现场跑**；
5. **"没做"不等于"有问题"**：属后续阶段/未接线的工作项计入"未落地"清单，不计为缺陷；
6. **同一事实只从一个来源取**，不叠加旧轮结论；每轮重新核对（代码在动）；
7. **引用设计写现役 `§N`**；归档引用必须带版本前缀。

## 1. 检查类别（逐类过，不挑着看）

每类带**前置证据**：先跑该类的命令并留下输出，再下判断。**没跑命令的类别一律记为"未执行"**，不得用概述语气蒙混。

### C1 集合与映射完整性

- 每个白名单 / 黑名单 / 映射是否覆盖其**定义域**？定义域在文档里时逐项对照。本仓重点：**禁词表（§12.3）**、**工具清单与拒绝序（§8.2–§8.4）**、**流程词汇表与保存门（§8.10–§8.11）**、**preset 行清单（§15.3）**、**Config 总表（§15.5）**、**World 分区表（§10.3）**、**水位线语义总表（§4.3）**。
- 手法（须实际执行并列出命中）：`grep -n "new Set(\|Record<\|readonly \[" src`，再逐项写出"定义域来源 → 覆盖情况"。
- **反向检查同样必做**：设计要求的字段，代码里**有没有写入点/消费点**（如 `onStateChange` 的赋值点是否全部迁移、`droppedLineCount` 是否有读者）；无写入点的记为问题或未落地。

### C2 外部 I/O 语义（send / sendCredential / 回调）

- 每处出站动作（`runtime.send`、`sendCredential`）与上行回调：是否按设计**去重 / 节流 / 标注未定**？逐处列出调用点与触发频率。
- **凭据类出站额外核**：返回值 / 日志 / 画面帧 / 语料里**是否可能出现明文**（§12.2 三道闸逐闸验证）。
- 设计只规定"去重"而未规定"本层去重"的，计为**质疑**，不计问题。
- 手法：`grep -n "\.send(\|sendCredential\|resolve(" src`，逐个回溯调用者与返回值来源。

### C3 状态生命周期

- 每个可变字段/状态：**谁写、谁清、有无孤儿**（写了没人读、置位没人复位）。
- 同时列出**一处状态两个表示**的情形（如 `conn` 与连接对象、`loggedIn` 与 World 的 `session` 分区），指出**权威方与同步点**（缺同步点 = 问题或未落地）。
- 手法：`grep -n "<字段名>" src` 全量，分别标注"写点/读点/复位点"；可变状态先枚举 `grep -n "private [a-z]\|let " src`。

### C4 代码 ↔ 设计逐条对表

- 现役各章的每条硬约束（判定序 `failOn > until > gaCount > maxLines`、`seen` 唯一真相、动作在路由前、拒绝序、环深护栏 32、步转移上限 256、出口 pass 掩码、闸门覆盖新通路……）**落到哪一行**；未落地者记入"未落地"。
- 手法：按 `§号` 逐条 grep 关键词，逐条给 `文件:行` 或"未落地"。

### C5 契约与边界

- 参数默认值与缺省语义；`undefined`/`null` 分支；同步抛 vs 异步 reject；断线/重连/复位路径；上界与溢出（缓冲、行数、超时钳制、环形淘汰）。
- 特别核：**可读拒绝 vs fail-loud throw 的分界**是否符合 §14.1。
- 手法：读每个导出函数签名 + 其 `return` 分支，构造最小反例逐个核对。

### C6 测试有效性

- 断言是否可能**空跑成真**；是否依赖时序（固定 `sleep`、依赖单次 write 成批到达）；是否覆盖各分支；是否改共享表；是否有**先红后绿**。
- **先跑再判**：只看 `vitest run` 结果不足以判定有效性，须逐条读断言。
- 手法：`grep -n "setTimeout(\|expect(" test`，对照分支清单。

### C7 文档一致性

- 注释 / 文档字符串与实现是否互斥；同一事实是否两种措辞；待实测项是否显式标注。
- **范围写死**：本轮**改动的全部文件**（不是只看新增段落、不是只看自己写的注释），逐句对照实现；未改动文件的注释只在"与本轮改动直接相关"时才查。
- 手法：先 `git status` / 文件行数变化确定改动清单，再对每个文件"注释句 → 实现行"成对列出；发现悬空引用（注释提到不存在的常量/函数/`§号`）即记问题。
- **本仓已知的历史教训**：`§16` / `§19` 等 v1 归档编号曾长期残留在 core3 注释里（§16.6）；新增注释一律写现役 `§N`。

## 2. 输出格式（结论固定写法）

```
## 本轮执行情况（逐类，先列这个）
| 类 | 执行的动作（命令/枚举） | 结果 |
|---|---|---|
| C1 | <命令> | <命中与对表结论，或"未执行"> |
| ... | | |

## 通过项（本轮复核）
- <事实>（文件:行）

## 问题（E1/E2/E3）
**N. <一句话标题>**
证据：<文件:行 / § / 命令输出>
修复：<一句话>

## 质疑（E4，不计为问题）
- <一句话疑问 + 为什么值得问>

## 未落地（不计为缺陷）
- <设计要求的机制，尚未接线/未实现>

## 待实测（不阻塞）
- <需真实语料或真实连接才能定的刻度>
```

`## 本轮执行情况` 表是**强制项**：每类必须有一行，未执行的写"未执行"并说明理由。**缺此表的结论视为不合规，可直接退回**。

## 3. 质疑的写法

质疑**只用来提问**，不夹带结论、不要求改。判据：若一条意见去掉"我认为应该"之后剩下的事实不足以说明它是错的，它就该是质疑。

## 4. 可重复执行的证据命令

```powershell
# 类型检查
pnpm --filter mud-core3 exec tsc --noEmit
pnpm --filter mud-workflow exec tsc --noEmit

# 测试（例数以当次实测登记，不硬编码历史值）
pnpm --filter mud-core3 test
pnpm --filter mud-workflow test

# 产物清单（判定"不存在"前必须先跑）
Get-ChildItem -Recurse -File -Include *.ts packages\mud-core3\src,packages\mud-core3\test
```

> 具体脚本以仓根 `package.json` 当次实际内容为准；E3 证据必须附命令与输出。
