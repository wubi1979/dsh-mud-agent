# §12 安全设计

## 12.1 威胁模型

| 威胁 | 场景 | 对策 | 章节 |
|---|---|---|---|
| **封号 / 被识别为 AI** | agent 参与聊天、公屏发言；不可逆命令被误发 | 聊天不进 agent（C5.2 已落地，§6.3/§17.4）；**禁发表**；回答不自动回流 | §12.3、§12.6 |
| **凭据泄露** | 密码进入日志 / 画面回显 / 模型上下文 / 公屏 | **零泄露三道闸** + 凭据动词双闸 + 只存引用名 | §12.2 |
| **跨账号越权** | 一个会话操作用户/工具去驱动另一个账号的连接 | 归属由**宿主谱系**决定；**不开 `sessionId` 参数**；祖先必须 live | §12.4 |
| **不可逆损失** | 删档类命令（`suicide`） | 禁发表最小集 + 全段扫描 | §12.3 |
| **行流污染** | 半开连接的迟到事件改变新连接状态 | **连接代次**：旧连接事件一律丢弃 | §3.2 |
| **上下文污染** | 密码或超长刷屏进入模型面 | 凭据不进上下文；单条投递上限 + 拆批；水位线防重复 | §5.4、§4.3 |
| **误报可见性** | 分类误报（C5.2 行打标）导致主屏少行 | 语料校准先行 + 规则 Config 可关兜底（§6.3、§17.4） | §17.4 |

## 12.2 凭据零泄露三道闸

| 闸 | 位置 | 机制 |
|---|---|---|
| ① **发送侧** | `sendCredential` | **不触发 `onSend`** ⇒ 不进画面回显、不进发送日志、不进语料 |
| ② **注入侧** | 流程动作的占位符 `{name}` / `{pass}` | 由**引擎注入替换**，**不经模型** ⇒ 明文不进上下文 |
| ③ **出口侧** | 解释器**出口统一过 pass 掩码** | 流程作者**忘写也不泄露** |

**配套约束**

- **凭据动词双闸**（§8.12）：`sendCredential` **只允许 locked 流程使用**——`registry.save` 静态拒 + 解释器执行侧 throw；`login` 是**全系统唯一凭据流程**。
- **只存引用名**：roster 存 `passRef`，页面只交引用名；明文只在宿主凭据域（§11.6）。
- **实时解析、不缓存**；解析失败报**引用名**（不报明文），且**失败在建连接/流程执行阶段**，不会出现"名字发出去了、密码是空串"的半截登录。
- **明文不出现在**：roster / 日志（含落盘 JSONL）/ 模型上下文 / 画面屏与帧 / 语料 / 错误信息。

## 12.3 禁发表与全段扫描

- **拦截表最小集 = `{ suicide }`**：删档不可逆，且任何正常玩法都不需要。
- **全段扫描**：命令按 `[\s;]+` 切分**全部 token**，**任一命中即拒**（堵 `look;suicide` 这类绕过）；拒绝信息**带命中词**。
- **判定位置**：拒绝序 ③，**先于连接判断**（安全最高优先，§8.4）。
- **放行项**：`quit` / `exit` / `drop` / `passwd` 等**不设拦**——可逆（`quit` 只是下线、`drop` 可捡回），拦它们会误伤正常玩法。
- **加行纪律**：**实证发现危险行为再逐行加回**；禁词表 Config 化后置（§17.3）。

## 12.4 归属与越权防护

| 措施 | 说明 |
|---|---|
| **归属 = roster 判定** | `sessionId ∈ accounts` ⇒ 是我们的会话；解析不到 ⇒ **零行为**（不是报错，是"与我们无关"） |
| **归属权威 = 宿主谱系** | 沿 `session.header.parentSession` 上溯（P1）；**插件不自建归属状态** |
| **祖先必须 live** | 与宿主 `authorizeLineage` 语义一致；不 live ⇒ 上溯终止 ⇒ **可读拒绝**（不以陈旧状态解析成功） |
| **环深护栏 32 层** | 防数据成环 |
| **不开 `sessionId` 参数** | `mud_send` 不接受 `sessionId`——**没有跨账号后门**；调用方身份只能来自宿主谱系 |
| **preset 不作归属门** | 按 preset 判归属会把选了 `standard` 的账号错误排除（§1.4） |
| **会话隔离** | 连接、行流、World、日志、画面一律按会话隔离（§5.5） |

## 12.5 接入闸门作为"进入面"唯一许可

- **闸门定义在通路集合上，不在单一机制上**（P5）：MUD→agent 的**进入面只有投递通道**，一切新通路落地必须**先回答"受不受闸门约束"**。
- 唯一例外：`mud_send`（应答经工具结果返回**调用方**，不产生"行进入 agent"，§6.5）。
- 显示通道（画面/状态/日志）是 MUD→**人**，不消耗 agent 预算，不经闸门（§6.4）。

## 12.6 回答回流 MUD 的唯一通道

- **投递通道是单向的**（MUD→agent）：agent 的回答**不会自动回流**到 MUD。
- **回流只有一条路**：`mud_send`（工具）或流程里的 `send` 动作——都由 agent 显式发起。
- 意义：agent 的"内心话"不会变成游戏里的发言，从结构上降低被识别为 AI 的风险。

## 12.7 不拦项与理由

| 项 | 不拦理由 |
|---|---|
| `quit` / `exit` | 可逆（重新登录即可）；拦它会让"断线重登"这类正常维护流程变复杂 |
| `drop` | 丢弃物可捡回 |
| `passwd` | 改密码是正常玩法；凭据明文不经此路径（§12.2） |
| 经济类危险操作（`steal`/`kill` 等） | 属"玩法选择"而非"不可逆损失"；**不做动态权限档位**，保持静态最小集（加行纪律见 §12.3） |
| 聊天/公屏 | **不由禁发表管**——由"聊天不进 agent"（C5.2 投递剔除，§6.3）从源头处置 |

# §13 观测与诊断

## 13.1 `SessionLog`（会话日志）

| 项 | 设计 |
|---|---|
| **粒度** | **每会话一个** `SessionLog` |
| **内存环** | 缺省 **2000** 条（`logBufferMax`）；装载运行 / 网络 / 投递 / 闸门事件 |
| **落盘** | 按天 JSONL：`<logDir>/mud-YYYYMMDD-<sessionId>.log`；**5MB 滚动 ×3**（滚动 = 真正分片重命名）；`seq` 从当日文件最大号续起；`logDir` 缺省 `<cwd>/mud-logs`，`logFile: false` 可关 |
| **原始行流** | **只落盘、不进环**（否则刷屏行会冲掉诊断信息） |
| **镜像** | `warn`/`error` 同时镜像宿主 `ctx.logger`（控制台可查） |
| **清理** | `removeAccount` 清理**该账号**的日志文件（只删本人文件） |
| **与上下文遮蔽的关系（T18）** | 遮蔽只改 **model-visible 表面**（§11.2）：被遮蔽的旧事件**仍在日志里**（可查、可回放），只是不进模型请求 |

**记录点（失败原因在这里，不再只有一句 remote 错误）**：登记 / 建连（含 `host:port` 与完整错误 `cause`）/ 凭据解析（带引用名）/ login 已发送 / 断连 / 探活（AYT 发送与判死计数；判活 link 内部消化不记日志，T12）/ 自动重连（每次尝试、放弃）/ 销毁 / 接入 / 停止 / 投递（批次、离线保留、缓冲溢出）/ 网络层（telnet 协商、断线、协议异常）。

## 13.2 诊断动词

| 动词 | 返回 | 面向 |
|---|---|---|
| `remote.mud.logs(sessionId)` | 环条目 + 落盘目录 | 会话头「MUD 日志」tab（§9.3） |
| `remote.mud.status(sessionId?)` | 连接/接入状态（带 `sessionId` 时附全会话列表） | 页面状态行、初始回填 |
| `remote.mud.watchStatus()` | 流动词：首帧全量 + 变化推帧 | 页面状态面（§9.5） |
| `remote.mud.follow(sessionId)` | 流动词：snapshot + 增量帧 | 画面 tab（§5.3） |
| `mud_state`（工具，§8.3） | 两轴 + World + recording/dropped | agent 自述 |

## 13.3 留痕口径（哪些必须留痕）

| 类别 | 要求 |
|---|---|
| **丢弃 / 截断 / 失配** | 必须有 error 日志 + 可观计数（环形淘汰 `droppedLineCount`、投递拆批、`until` 失配） |
| **降级** | 必须 `warn` **点名**（哪个域/服务不可用、退到什么模式、后果是什么）——见 §14.3 |
| **连接失败** | 必须带 `host:port` + 完整 `cause` |
| **凭据** | **任何日志/错误都不得出现明文**（只报引用名） |
| **原始行** | 只落盘、不进环；语料与日志分离 |
| **结构化失败** | 流程 timeout 出口**点名步骤**（不静默，§8.13） |

## 13.4 语料与回放

- `link/corpus.ts`：行流按 JSONL **全量落盘**并可读回（§3.5）。
- 回放用例是 `link/` 层的**主测试手段**（先红后绿，§16.1）。
- **语料校准**是 C5.2（行打标与画面分屏）的**第一步**——已执行（2026-10-03，chat 规则语料 6/6 命中零误报后定稿，§17.4）。

# §14 错误处理与降级

## 14.1 可读拒绝 vs `throw` 的分界

| 情形 | 处置 | 判据 |
|---|---|---|
| 模型可据此**改变行为**的失败（引擎缺席、未绑定账号、禁词命中、未连接、持有者冲突、未登记会话、凭据引用失效） | **可读拒绝**：`{ok: false, error}` 或结构化 remote 错误，**不 throw**（P8） | "模型读了能换条路走" |
| **契约 / 配置 / 代码错误**（工具注册不完整、流程 schema 不合法、`goto` 目标不存在、`silenceMs` 非正整数、`sessionId` 必填缺失） | **fail-loud `throw`** | "这是 bug 或配错，必须吵" |
| 程序内部不变式被破坏 | **fail-loud** | 同上 |

**共同纪律**：拒绝文本一律是**面向模型/人的可读文本**，带**足以定位的上下文**（命中词、引用名、步骤名、`host:port`）。

## 14.2 失败不丢行 / 失败不推进水位

| 失败 | 处置 |
|---|---|
| 投递回调返回 `false`（agent 离线 / `followup` 抛错） | 批次**不推进** `deliveredAbs`；行留在 `pendingLines`；`agent/created` 时 `flushPending` 补投；下次 flush 从**失败点**自然重试（P7） |
| 投递抛错 | 同上 + `warn` |
| 单条超限 | **拆成多条依次投递**，不静默丢行（§5.4） |
| 环形淘汰 | 丢**最旧**行 + 自增 `droppedLineCount`（可观，不静默） |
| **断线** | **例外**：`pendingLines` 与未投批次**一并复位**（录制语义，§4.5）——与"断线是硬收尾"一致 |

## 14.3 宿主能力缺面与降级总表

| 缺面 / 失败 | 降级行为 | 可见性 |
|---|---|---|
| `storageDomain` 尚未 provide | **可选依赖三态**：同步命中即挂 / `ctx.inject` 等域就绪再挂 / `rosterStorage:false` 强制内存；**内存先行**，域挂上后**迁入**（迁移幂等）；RPC 不等域 | `warn` 点名 |
| storage 域打开失败 | 名册退回内存（**重启丢服务器/账号**） | `warn` 点名 + 真实错误打到控制台 |
| `mud_workflow` 域不可用 / 迁入失败 | 流程注册表退回内存（**记录与账本同在内存降级层**；迁入失败时**不挂域、不清内存**，内存仍是唯一真相） | `warn` 点名（含取新落败的记录名） |
| `typert` 不可用 / 工件未生成 | 只记 `info`，remote 通道不可用 | `info` |
| `credentials` 服务缺席 | 抛可读错（"宿主凭据服务不可用"） | 错误 + 日志 |
| 凭据引用不存在 / 不可读 | 流程执行失败，**报引用名** | 错误 + 日志 |
| `sessionController` 缺席 | 抛"无法建会话"，**名册回滚** | 错误 + 日志 |
| `agents` 不可用 | 归属上溯终止 ⇒ 工具**可读拒绝** | 拒绝文本 |
| 画面 follower 超限 | **显式断流**（不是静默丢帧）；重新 follow 以新 snapshot 恢复 | 客户端可感知 |
| 插件重启 | 画面屏（headless）清空；名册/流程域保留 | — |

## 14.4 结构化失败

| 场景 | 结构 |
|---|---|
| 流程等待收束（`timeout`/`quiet`/`signal`/`disconnected`/`danger`） | 一律走 **timeout 出口**，语义 = 放弃等待、帧未提交，**现场行随结果返回**；**无 `next` 且 `branch` 未命中 ⇒ 点名步骤**（§8.13） |
| 流程 `failOn` 命中 | 按 `onFailOn` 声明的**分类出口**返回（如 `need-new` / `bad-pass`） |
| 子 agent 失败 | **立即停止**，收尾文本写明现场（已完成 / 未完成 / 卡在哪），作为 `subagent` 工具结果（`isError`）回到根（§7.6） |
| 子级预算 | **本版无子级预算机制**（后置，§17.3）；子自身的超时以收尾文本随工具结果返回 |

## 14.5 已知限制与"不引机制"清单

| 限制 | 现状 | 触发条件（到了才做） |
|---|---|---|
| 超长回合 + 持续刷屏 | `pendingLines` 可累积至环形上限；`turn/end` 一次拉取可能拆多条 followup 排队 | token 账目恶化（§17.3 投递策略化） |
| **会话删除面缺口** | 删账号后会话仍在宿主内（§2.4）；每次委派留下的子会话记录与父会话目录条目同样无清退面（只读留存，§7.6） | 宿主补面 |
| `watchStatus` 边界窄面 | **已收口（T11）**：行面 = `StatusRow`（`statusRowOf` 映射，`loggedIn` 直传 + `world` 扁平数组值字符串化） | §9.5 |
| `ask_user_question` 无超时 | 无人应答永久挂起 | 确认"无人应答必须超时"的实证（§17.3） |
| 画面历史不持久化 | headless 屏随 runtime 存活，**插件重启即清** | 需要跨重启回放时 |
| send 回显与 MUD 自回显 | 可能重复显示 | 实证出现重复时加去重开关（§17.3） |
| 无自动重连 | 手工 `connect` | **前置 = 真实心跳**（无心跳不区分真断线/半开连接，§17.3） |
| 解释器无沙箱 | 进程内执行 | 不引：JSON 白名单 + schema 已构成静态可验证的安全边界（§8.9） |
| 流程表达力 | 无循环 / 计算 / 条件 | "JSON 表达不了"的例证（§17.3） |
