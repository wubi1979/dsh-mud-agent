# mud-core 设计四稿：自主玩家·五层心智（design4）

- 状态：**设计提案**（2026-09-24，供与 design1 / design2 / design3 对比评审）
- 方法：不从 DSH 底层出发，以游戏与玩家心智为模型；**先干后支**——主干 = T2 闭环及其最小执行形态（计划编制 → 单子 agent 串行执行 → 结算回注 → 检视）；沉淀与优化机制只在主干跑通后作为支加入
- 与前三稿的关系：本文是讨论收敛稿。design1/2 的执行资产（入站链、wait 竞速、凭据流程）作为实现细节继承；design3 的沉淀思想降级为技能的生成来源；三稿的"流程层/习惯执行权"全部清算

---

## 1. 第一原则与设计顺序

**以"自主玩家"为模型，以 token 预算为第一约束。**

两条推论：

1. **agent 的价值在于类人的灵活与自主。** 架构的责任是保护这种灵活性，而不是用程序结构替换它——把 agent 编制成机器，就完全不必引入 agent。前三稿的共同毛病都在这里：它们把"省 token"回答成了"把 agent 的一部分机器化"（原语化、流程层、习惯重放）；
2. **T2 路径先于一切机制。** 作者已实证：入站信息驱动 + 静默到期唤醒 + 大模型 = 完整自主行为（自己取钱、买食物、去茶室喝水、看地图找路），唯一卡点是 token 成本。所以 T2 路径不是待建设的能力，而是已被证明存在的主干——设计的工作是给它一个省 token 的组织形式，不是替它玩。

设计顺序由此确定：主干 = T2 闭环自身——三个唤醒源、唤醒上下文、计划编制、**单子 agent 串行执行**、结算回注、检视（§9 的"干"）；**子 agent 是主干的执行半边，不是支**。技能沉淀、教训库、反射表、模型降档全部后置（支）。

## 2. 五层心智模型

| 层 | 定义 | 类人对应 | 成本 | 纪律 |
|---|---|---|---|---|
| **存在** | MUD 信息联通：连接生命周期、行流、世界状态维护 | 神经系统的物理在场 | 0 | 世界状态是唯一真相，所有层读同一份 |
| **反射** | 命令直发：save、翻页、协议应答——刺激→动作，不问为什么、不管后果 | 膝跳反射——不经觉察 | 0 | 只放**天然无后果**的机械反应（反射层不做后果评估，入选者必须自带无害）；需要"知道为什么"的动作归意识层 |
| **意识** | 规则动作：持续感知（世界抓取、危险觉察、**占线活动跟踪**）+ 条件触发——觉察到危险 → halt 解锁 + 唤醒；子 agent 上报 → 唤醒 T2。**越界（HP 缓降、未遭攻击）不单独唤醒**——越界事实维护进世界状态，随静默环顾的唤醒摘要上浮（§3.2） | 持续知觉与条件反应——看到车冲过来猛地停下（知道为什么停） | 0 | **必须薄**：只感知与触发，不解释。往意识层加理解 = 违反 T2 优先 |
| **思考** | T2：接收信息 → 目标 → 计划 → 检视 → 学习 | 前额叶——意图与 deliberation | 每次唤醒一次调用 | 唯一持有目标与意图连贯性的层 |
| **记忆** | 经验教训 | 海马沉淀 | 注入成本 | 三分：工作 / 陈述 / 程序（见 §6） |

```
                ┌─────────────────────────────┐
                │ T2 思考层（低频、贵、意图连贯）     │
                │ 接收信息→目标→计划→检视→学习       │
                └──────┬───────────────┬─────┘
                计划下发│           ↑报告/上报/危险唤醒
                ┌──────▼───────────────┐
                │ 子 agent（被动式执行者）   │
                │ 无目标智能·有执行智能      │
                │ 引用技能=程序记忆          │
                └──────┬───────────────┘
                       │发命令
   ┌───────────────────▼──────────────────┐
   │ 反射层：save/翻页直发（无觉察的机械反应）   │
   │ 意识层：世界抓取+危险觉察+条件触发（薄）    │←永续，向所有层供给状态
   │   觉察到危险 → halt 解锁（保行动自由）      │
   │ 存在层：连接、行流、世界状态                │
   └──────────────────────────────────────┘
   记忆：工作（世界状态）/ 陈述（教训）/ 程序（技能流程）
         学习沉淀 ↑    唤醒/任务注入 ↓
```

## 3. T2 思考层：闭环与唤醒

### 3.1 闭环

```
唤醒 → 组装上下文 → 思考（消化结算报告 / 目标 / 计划 / 学习）
     → 下发计划（要点 + 边界声明 + 战术教训）
     → 子 agent 串行执行（引用技能/流程）
     → 结算即唤醒，报告回注会话
     → T2 消化该次结算并检视在途计划 → 经验教训沉淀
```

### 3.2 三个唤醒源（收敛）

| 唤醒源 | 对应人的注意力回归 | 条件 |
|---|---|---|
| 静默到期 | 主动环顾——"没事且没事干" | **且无计划在途**（子 agent 正在执行 = 有事在干，不打扰） |
| 意识层危险唤醒 | 惊吓 | 立即，不等静默期；判据 fail-closed（死亡/断线/攻击） |
| 子 agent 上报 | 下属汇报 | 受阻 / 完成 / 越界请示 |

越界不设第四源（定案）：HP 缓降、进入战斗这类世界越界由意识层抓取进工作记忆，**在静默到期的唤醒摘要里呈现**——静默环顾本来就要带世界状态，越界事实搭这一次车，不单独立计时器、不单独立唤醒理由。代价是"HP 开始跌"到"T2 知道"有一个静默期延迟；遭攻击有行可警的场景仍走危险源立即唤醒，不受影响。

### 3.3 结算即唤醒（定案，检视仍为计划级）

整体规划需要积攒变化，一步一请示是浪费——"异步"的确切含义是**要点级不打断**：计划执行中，子 agent 不为单个要点向 T2 请示，意外自行消化；只有受阻、完成、越界请示三种结算才回到 T2。

**完成也唤醒，且这是宿主定形、不是可选项**：DSH continuable 子 agent 的结算通知必然投递到父会话——父空闲则开新回合（followup）、父运行中则步边界插话（steer），源码没有"只落日志、等自然醒"的第三态。因此 §3.3 不再承诺"完成报告攒到下一个自然唤醒点"，而是：**结算即唤醒，检视是计划级的**——一次醒来消化该次结算并顺带检视在途计划，而不是每个要点醒一次。token 代价明码入账（§7：每份计划约 2 次 T2 调用：编制 + 结算检视）。

### 3.4 唤醒上下文组装（token 账单的大头）

每次唤醒的组装 = 身份（persona）+ 世界状态摘要 + **在途计划进度** + 未消化报告 + 相关教训。计划必须持久（落在会话日志）——干到一半忘了干啥，人看手里的清单想起来，唤醒时在途计划就在上下文里。这个组装是独立组件，遵循克制原则：只给 T2 本次决策需要的。

## 4. 子 agent：被动式执行者

### 4.1 定义（四条）

1. **无目标智能**：不生成目标、不质疑意图——它的会话里没有"要不要"的问题，只有"怎么完成"；
2. **有执行智能**：保留解决问题的能力（走错路会看地图——作者实证的自主能力大半在此层重现）。执行细节全权：前提不成立的步骤跳过、执行意外自行处置；
3. **被动式**：不订阅世界状态，不主动发现任何需求（不会"发现你口渴了帮你端茶"——口渴饥饿是 T2 需要知道并规划的事）；生命周期 = 任务生命周期：接到要点 → 执行 → 报告 → 消亡，无常驻、无自主唤醒；
4. **一个计划一个子 agent**：计划可含 N 条要点，由同一个子 agent **串行**执行（任务并行在单连接的 MUD 中意义不大）；要点级拆分作为后置优化。

### 4.2 形态

DSH 原生 subagent（独立会话、隔离、结果回注）——独立会话天然实现"无目标"：它看不到主体的历史包袱，世界里只有任务；隔离同时是安全。同会话执行模式做不到这一点（带着 T2 全部历史，必然"有想法"）。

上下文组装：任务要点 + 边界声明 + 相关战术教训 + 执行所需的状态窗口——**不含全量历史**。"知道自己在做什么" = 任务上下文 + 执行中的即时感知，来自意识层向所有层的持续供给。

### 4.3 权限与边界

- **边界声明随计划要点自带**（预算上限、禁止事项），**编译为宿主原生权限执行**——子 agent 会话 `tools/pre-execute` deny 交易/不可逆类工具 + `tools.restrict` 遮蔽危险面，根会话放行；权限的数据在计划里、牙齿在宿主工具管线上，不是自建机制层；
- **人工交互只在根会话**：宿主规定被父拥有的子 agent 调 `userQuestions` 直接拒绝（DELEGATED_CALLER）——子 agent 遇到必须问人的事，把问题装进结果上浮，由根问人兜底（fullme 见 §5.1）；
- **紧急处置权**：仅限可逆的即时动作（逃跑 / 停手 / 喝药），不上报；不可逆动作（交易、丢弃、交任务）**不在子 agent 权内**——身体可以本能躲闪，不会本能地买卖贵重物品；
- 处置不了 / 没见过的危险 → 中断执行，携现场上报 T2（目标级重规划）。

## 5. 三个问题的解

### 5.1 计划要点匹配到固定流程 → 流程资源化

流程对计划是**词汇，不是平行执行者**。技能/流程目录对 T2 可见（计划编制时引用）、对子 agent 可调（执行时调用）；DSH skills 机制（SKILL.md 给模型看、模型照着做）承载此职能。凭据流程（login / fullme）保持代码身份，但对模型只暴露 `mud_flow('login')` 一个工具调用——密码不进任何模型上下文。

**fullme 的人工链定案：工具优先，问人是根侧兜底。** fullme 是**子 agent 可调的标准流程**（收图 → 调图片识别工具取码 → 发码完成），不再设计"流程内挂起问人"。识别工具的承载当前不存在（待研究），接口按正确形态先立、实现返回必然失败——失败路径就是现阶段的真实路径：流程以 `{ done:false, question }` 结束 → 问题随子 agent 结算上浮 → **根会话** `userQuestions.ask()` 问人取码 → 带答案续跑或重跑。识别工具未来接通时只换实现，链路不动；且子 agent 本来就被宿主禁止问人（§4.3），兜底落在根不是选择而是宿主强制——设计与强制同构，不存在"忘了降级"。

design3 的习惯沉淀降级为**技能的自动生成来源**，不再有执行权。

### 5.2 计划中的无关内容 → 不做净化机制

计划是**意图快照，不是合同**。人拿到的计划总有废话，人从不卡在"这条好像没必要"上——执行智能消化：前提不成立的步骤跳过，走到半路路线失效就改。步骤级自决、目标级上报。要改的是计划编制的质量（提示词与示例），**不是为模型的平庸输出设计防御机制**——那就是把它编制成机器。

### 5.3 紧急情况 → 三级响应，恰好对齐三层

| 层级 | 场景 | 机制 |
|---|---|---|
| 意识（0ms） | 遭袭/叫杀时的第一反应 | **halt 解锁**——释放占线活动，保证后续动作（逃/战）可发；只解锁不定向，逃还是战由预案/T2 决策；觉察后视判据级别同时唤醒 |
| 子 agent（执行智能） | 计划内的常见意外、可逆即时处置 | 预案动作，不上报；处置不了携现场上报 |
| T2（重规划） | 目标级变化、没见过的危险 | 携现场唤醒 |
| 硬底线（fail-closed） | 死亡 / 断线 / 凭据 | 意识层代码直接拦截一切，不依赖任何模型 |

现行 mud-core 最复杂的"打断仲裁"域（priority 比大小、interrupts 准入、复位、残余队列清除）在此模型下结构性不存在——没有两个执行者争控制权，只有单向的"处置不了就升级"。

### 5.4 反射与意识的分界（作者定案）

分水岭是**"知道为什么"**：

- **反射（save、翻页）**：刺激→动作。不需要知道为什么做出这个动作，后果是什么也不管——因此只放天然无后果的机械反应（save 多发无害、翻页多发无害）；
- **意识（halt）**：觉察→触发。halt 需要意识到危险（知道为什么要停）才成立——属意识的触发输出，借直发通道发出（快），但决策是觉察，不是脊髓反应。

误判后果示例：若把 halt 放进反射层，"遭袭"就得写成行文特征→命令的映射表——危险形态每多一种就得改一次表，且无法解释为什么发。放在意识层，它共享危险觉察的同一份判据（与唤醒 T2 同源），觉察到什么程度该停、该醒，是一个连续谱而非两张表。

### 5.5 halt 的完整语义（作者定案：四例定标）

halt 不是防御动作，是 **MUD 的通用解锁原语**：释放当前占线活动，使角色可接受新指令。四个实测用例：

| 场景 | 占线活动 | 想做的新动作 | halt 的作用 |
|---|---|---|---|
| 血底逃跑 | 战斗状态 | 移动逃跑 | 解锁移动 |
| 读书收 fullme | 读书 | 发 fullme<码> | 解锁发送（探测命令不占线可直发） |
| 打坐被叫杀 | 打坐 | 逃/战 | 解锁反应（否则原地不还手被打死） |
| 慢速房间想吃 | 移动（3s/房） | 进食 | 解锁进食 |

三条推论：

1. **halt 永不单独出现**——它总以"halt → X"对子存在，服务的永远是下一个动作；halt 自己不解决任何问题，只解决"现在还不能开始做"；
2. **依赖世界状态的占线活动字段**——正在战斗/读书/打坐/移动。世界抓取必须抓这个字段；
3. **命令粒度的 busy 兼容性是游戏知识**——哪些命令会被占线拒绝（fullme 探测不被拒、fullme<码> 被拒）无法机制推断，逐命令实测。

**双路径归属**：

| 路径 | 归属 | 机制 |
|---|---|---|
| 紧急（被叫杀等危险觉察） | **机制**（意识层） | 觉察 → halt 解锁（fail-safe：保"你能动"，不管"往哪动"）+ 视级别唤醒。不能靠学习，会死人 |
| 常规（切换活动前的 halt 前置） | **知识**（程序记忆） | 技能/流程里写明 halt 前置；`你正忙着` 这类服务端拒绝是天然教育信号——子 agent 收到 busy 错误 → 补 halt 重试（执行智能，无新机制） |

人就是这么学会 halt 的：新手被"你正忙着"教育几次就懂了，agent 走同一条路——**紧急 halt 是机制（不能靠学习），常规 halt 是知识（应该靠学习，不硬编码）**。

**结构性对偶**：游戏侧是单活动模型（同一时刻角色只能占线一个活动，halt 是让出命令）——与 agent 侧单持有者（同一时刻只有一个东西占行流）精确对偶。两侧的"忙"语义同构，子 agent 的执行循环天然贴合游戏的占线循环。

## 6. 记忆三分与学习回路

| 类型 | 内容 | 技术承载 | 注入点 |
|---|---|---|---|
| **工作记忆** | 世界当前状态（HP / 口渴 / 位置 / 登录态 / **占线活动**） | 世界状态（意识层维护） | 所有层读同一份 |
| **陈述记忆** | 经验教训（"那个店周三不开门"、"死后先捡尸体"） | 教训库（上限条数，超限由 T2 归纳合并——人会遗忘，记忆会压缩） | 战略教训 → T2 唤醒上下文；战术教训 → 子 agent 任务描述 |
| **程序记忆** | 技能与流程（"去茶室的走法"、login） | skills 目录（人写种子 + 模型沉淀） | 计划编制引用、子 agent 执行调用 |

学习因此有双产物：**教训（陈述，来自检视失败与意外）+ 技能（程序，来自检视成功的要点沉淀）**。token 成本随记忆积累单调下降——走老路不重新思考。

## 7. token 账目

| 项 | 成本 | 说明 |
|---|---|---|
| 存在 / 反射 / 意识 | 0 | 代码 |
| T2 | 低频 × 单次贵 | 三源唤醒；**结算即唤醒**（§3.3）——要点级不请示，计划级必检视 |
| 子 agent | 每计划 1 次启动 + 若干次 × 上下文小 | **同模型下省的是上下文尺寸**：T2 上下文 = 全量历史+目标+计划（大），子 agent 上下文 = 要点+状态窗口+战术教训（小）。**结算唤醒 1 次/计划为宿主定形的固定成本**（§3.3）。模型降档（子 agent 用便宜模型）是二期优化，先跑通账目 |
| 技能引用 | 0 | 已沉淀的要点执行近乎零思考 |

**成本上限 = 现状（修正表述）**：主干含子 agent 后，"每步一次 T2 全量调用"变为"每计划一次 T2 编制 + 若干次小上下文子 agent + 1 次结算唤醒"——**长计划净省、短计划未必**（1–2 步的计划，子 agent 冷启动+结算可能高于 T2 直跑）。因此上限主张收窄为：**同场景账目不劣于现状，由验收逐场景断言，恶化即回退**；技能库、教训库全空不影响此结论（它们只影响支的曲线）。

## 9. 实施顺序（先干后支）

**干（T2 最小闭环，含子 agent——§1 定案）**：三个唤醒源 + 唤醒上下文组装 + T2 计划编制（要点+边界声明）+ 单子 agent 串行执行 + 结算回注（即唤醒）+ 计划级检视 + 权限编译（pre-execute/restrict）+ fullme 工具优先/根兜底链。全部接在已实证的入站/唤醒机制上。

**验收**：作者已实证的四行为（取钱 / 买食物 / 喝水 / 找路）在新账目下复现，用行为账目护栏——**模型步次数（`step/start` 事件，不用 `request/header`）== 真正需要模型决策的次数**，对照实证基线逐场景断言；**四行为必须至少一次走"计划→子 agent→结算"全链路**（否则测不到干）；fullme 单列一条：识别工具失败 → 问题上浮 → 根问人 → 续跑，断言全程无子 agent 侧问人。
