## 需求与安全前提

- **需求**：把聊天、其他玩家的动作从游戏输出中提取到副屏窗口——方便人观察 + 帮 agent 去噪。
- **安全前提（用户裁定）**：聊天不进 agent——AI 识别/发言有游戏串行干扰与被识别为 AI 玩家导致封号的风险；agent 不能回复聊天，投递侧直接剔除有标行（含他人动作，缺省）。

## 核心裁定（最终形态：保留 C5 无头屏机制，双屏出帧时拆，客户端各自获取）

1. **标在 `MudLine` 上**：加 `kind: string | null` 字段；分类器在 `runtime.onLine` 单点写入——**全系统唯一一次分类**，分类与路由判定都在服务端；
2. **保留全部原始路径（用户裁定）**：无头屏 + SerializeAddon + 写操作链 + follower 机制**零重构**；GameScreen 内部变为**两个无头屏**——`termMain`（无标行 + send 回显）与 `termSub`（有标行），**互斥完备**（并集 = 全部行）；各自挂 SerializeAddon；
3. **帧双串（构造帧时拆）**：snapshot 一帧双字段 `screenMain` / `screenSub`（同一条操作链内同时 serialize——attach 原子性天然保持）；output 一帧双字段 `main` / `sub`（本批无标行 join / 有标行 join）；**不是两条流、不是两个 follower 集**——帧变胖对应内容，队列/背压/断流重连语义零改动；
4. **客户端纯渲染**：s1（主 xterm）只吃 `screenMain`/`main`，s2（聊天栏）只吃 `screenSub`/`sub`，前端零 kind 逻辑；state 帧不动，直通工具栏。

## 帧结构（`view/screen.ts`）

```ts
interface GameSnapshotFrame {
  type: 'snapshot'; sequence: number
  screenMain: string   // termMain serialize（主屏历史，只含无标行）
  screenSub: string    // termSub serialize（副屏历史，只含有标行）
  info: GameViewInfo
}
interface GameOutputFrame {
  type: 'output'; sequence: number
  main: string         // 本批无标行 join（含行尾）
  sub: string          // 本批有标行 join（含行尾）
}
// GameStateFrame 不变
```

## core3 侧

- [line.ts] `MudLine` 加 `kind` 字段：`commitLine` 缺省置 null；link 层保持纯净；

## webui 侧

- **s1 主 xterm**：现有渲染逻辑不变，仅字段换名（`frame.screen` → `frame.screenMain`、`frame.data` → `frame.main`）；快照回放/增量/state 照旧；

- i18n：locales.ts 补 zh/en。

## 利弊结论（定稿时分析，恢复执行时先复核）

**利**：

1. 机制零重构 = 风险面最小：C5 实机跑通的无头屏/操作链/follower 语义全保留，C5 七条用例仅字段改名 + sub 屏断言；
2. 一处真相且全在服务端：规则更新 = 后端重启即生效，无前后端规则不一致问题；
3. s2 白赚 serialize 级回放（聊天历史跨刷新/tab 重开不丢）；主屏 live/replay 一致（都只含无标行）；
4. 一帧双字段保住 attach 原子性（非两条流/两个 follower 集，独立通道的全部缺点不存在）；
5. 前端改动极小（s1 换两个字段名，s2 纯渲染新组件）。

**弊**：

1. **误报可见性反转（最需敬畏）**：互斥路由下分类误报 = 「主屏少一行」（只出现在副屏），不再是「副屏多一行」——必须语料校准先行 + 剔除规则可关兜底；
2. 双无头屏开销：两块格点 buffer（总行数不变分家而已，约 2–4MB/会话，多会话线性）+ 操作链等两次 drain——可忽略量级；
3. 帧双串带宽耦合：每个 follower 收 main+sub 全量；若将来 s2 独立成 tab 会双份，届时加 view 参数或接受冗余（已列后置）；
4. sub 屏版式：serialize 按服务端 cols 成形，副屏窄栏二次 wrap/横滚（服务端定宽方案的通病）；
5. send 回显固定进主屏：二期 agent 若发聊天命令，副屏聊天记录不完整（后置）；
6. s2 空态 UI（会话初期 `screenSub` 近乎空串）。

**结构总结**：用第二块无头屏的内存/版式小开销，买机制零重构 + s2 回放 + 规则单点。相比行环方案：行环省内存省依赖但动 C5 机制核心；保机制风险最低，符合「优先实机验证路径」取向。
