## 需求与安全前提

- **需求**：把聊天、其他玩家的动作从游戏输出中提取到副屏窗口——方便人观察 + 帮 agent 去噪。
- **安全前提（用户裁定）**：聊天不进 agent——AI 识别/发言有游戏串行干扰与被识别为 AI 玩家导致封号的风险；agent 不能回复聊天，投递侧直接剔除有标行（含他人动作，缺省）。

## 核心裁定（最终形态：保留 C5 无头屏机制，双屏出帧时拆，客户端各自获取）

1. **标在 `MudLine` 上**：加 `kind: string | null` 字段；分类器在 `runtime.onLine` 单点写入——**全系统唯一一次分类**，分类与路由判定都在服务端；
2. **主屏无头屏 + 副屏行环（2026-10-03 修订）**：保留主屏全部原始机制（无头屏 + SerializeAddon + 写操作链 + follower 机制**零重构**——风险权衡，非语料上的技术必需，见修订说明）；`termMain`（无标行 + send 回显）保持无头屏，副屏降为**有界行环**（有标行 `MudLine` 追加，cap 行数，超限丢最旧）——副屏纯行式内容（实测零光标寻址）无需 VT 栅格，join 即回放；
3. **帧双串（构造帧时拆）**：snapshot 一帧双字段 `screenMain` / `screenSub`（同一条操作链内**同时取值：主屏 serialize + 副屏行环 join**——attach 原子性天然保持）；output 一帧双字段 `main` / `sub`（本批无标行 join / 有标行 join）；**不是两条流、不是两个 follower 集**——帧变胖对应内容，队列/背压/断流重连语义零改动；
4. **客户端纯渲染**：s1（主 xterm）只吃 `screenMain`/`main`，s2（聊天栏）只吃 `screenSub`/`sub`，前端零 kind 逻辑；state 帧不动，直通工具栏。

## 帧结构（`view/screen.ts`）

```ts
interface GameSnapshotFrame {
  type: 'snapshot'; sequence: number
  screenMain: string   // termMain serialize（主屏历史，只含无标行）
  screenSub: string    // 副屏行环 join（有标行历史，行原文含 ANSI）
  info: GameViewInfo
}
interface GameOutputFrame {
  type: 'output'; sequence: number
  main: string         // 本批无标行 join（含行尾）
  sub: string          // 本批有标行 join（含行尾）
}
// GameStateFrame 不变
```

## 利弊结论（定稿时分析，恢复执行时先复核）

**利**：

1. 机制零重构 = 风险面最小：C5 实机跑通的无头屏/操作链/follower 语义全保留，C5 七条用例仅字段改名 + sub 屏断言；
2. 一处真相且全在服务端：规则更新 = 后端重启即生效，无前后端规则不一致问题；
3. s2 白赚 serialize 级回放（聊天历史跨刷新/tab 重开不丢）；主屏 live/replay 一致（都只含无标行）；
4. 一帧双字段保住 attach 原子性（非两条流/两个 follower 集，独立通道的全部缺点不存在）；
5. 前端改动极小（s1 换两个字段名，s2 纯渲染新组件）。

**弊**：

1. **误报可见性反转（最需敬畏）**：互斥路由下分类误报 = 「主屏少一行」（只出现在副屏），不再是「副屏多一行」——必须语料校准先行 + 剔除规则可关兜底。（2026-10-03 行环修订补记：误报落点仍是主屏缺行——主屏保留无头屏，行环化**不降低**此项成本；但它解锁了**低置信行双投**兜底选项：判据不确定的行同时写主屏与副屏，行环重复一条无害、无 VT 状态互斥约束，误报不再必然意味着主屏缺行。若采纳双投，测试面 3 的互斥完备断言需同步放开——见测试面注。）
2. 主屏无头屏开销不变：一块格点 buffer（约 2–4MB/会话，多会话线性）+ 操作链 drain——副屏已降为行引用数组（cap 1000 行），开销可忽略；
3. 帧双串带宽耦合：每个 follower 收 main+sub 全量；若将来 s2 独立成 tab 会双份，届时加 view 参数或接受冗余（已列后置）；
4. ~~sub 屏版式：serialize 按服务端 cols 成形，副屏窄栏二次 wrap/横滚~~（**2026-10-03 消除**：副屏行环不限 cols，客户端自由 wrap）；
5. ~~send 回显固定进主屏：agent 若发聊天命令，副屏聊天记录不完整~~（**由安全前提排除**：聊天不进 agent、agent 不回聊天——agent 不存在「发聊天命令」场景；agent 发其他命令的回显本就属于主屏内容）；
6. s2 空态 UI（会话初期 `screenSub` 近乎空串）；
7. （2026-10-03 改写）副屏行环 cap 语义需明确：按**有标行条数**计数（缺省 1000），与主屏 2000 行**全量输出**是两种不可比的深度单位——聊天行稀疏，行环的时间跨度通常**远长于**主屏 scrollback（主屏几分钟即滚走）。若需对齐时间跨度，按实测有标行密度反推 cap；观察面可接受，需要时调。

**结构总结（2026-10-03 修订后）**：主屏保留无头屏机制（C5 零重构），副屏降为有界行环——用一份行引用数组（内存可忽略）买 s2 回放 + 规则单点，省掉第二块栅格 buffer 与第二次 drain，顺带消除 cols 定宽对 s2 的版式约束。主屏侧不变：相比行环替代主屏（已否决），保机制风险最低，符合「优先实机验证路径」取向。
