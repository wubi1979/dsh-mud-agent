# P1 预案档（0ms 战斗响应）草案

> **状态：起草中（待作者裁决）**。取材：2026-09-25 关于"遇险 → 唤醒根 → 派子级 → 选技能 → 战斗"延迟不可用的讨论。
>
> 待裁决 3 条见第 6 章；裁决前本计划不得作为实施依据。

## 第 1 章 元信息与范围

### 1.1 覆盖项

1. 新增**预案档**（0ms 档）：判据从"严重性"推广为"**从信号到必须动作的时间窗是否小于一次模型调用的耗时**"。
2. 修订 §5.5 的反射/意识分界：补一条**正交的时间预算轴**。
3. 兑现 §5.6 已写但无承载的词"预案"（design4 §5.6 两处提及，impl 全文零承载）。
4. 明确预案的**释放阀门**口径（以结束标志为主判据，断线与步级超时为兜底）。

### 1.2 目标

1. **叫杀 → 出招的时延从"秒级以上"降到"同一行流处理内（毫秒级）"**，全程 0 次模型调用。
2. 战斗的**回合级分支**由代码承担（读世界状态决定下一招），模型只在**战后**介入。
3. 不引入第二个执行者：预案只含"触发条件 + 动作"，不含目标选择。

### 1.3 非目标

- **不做抢占**：预案在行流被他人持有（子级在途）时**不接管**管理循环。理由：抢占即打断仲裁，§9 明确不做。
- 不做预案看门狗、不做预案总时长硬上限、不做预案数量上限（见 3.4）。
- 不做预案自动生成（第一期人工写种子）、不做预案嵌套、不做预案组合编排。
- 不改反射档（`REFLEX`）的入选纪律与语义。

## 第 2 章 背景与核心决策

**背景**：现行链路"危险命中 → `steer` 唤醒 T2 → T2 派单子 agent → 子级读技能 → 战斗"在时间上不可用——MUD 从"叫杀"到对方第一招只有 1~2 秒，而一次模型调用是秒级，`subagent` 派单还要额外承担新会话冷启动。人类玩家的形态是两段：**安全时编制定式（慢、有意图）+ 战斗中触发器直接执行（0ms、无决策）**，回合结束才看交换文本决定下一步。

**现状缺口**：design4 §5.6 的"硬底线"（死亡 / 断线 / 凭据 —— 意识层代码直接拦截，不依赖任何模型）已经把判据指向"不由模型决定"，但它用**严重性**划范围，漏了**时间**这一维。§5.6 意识层一行写着"去向由**预案**或 T2 决定"、子 agent 一行写着"**预案**动作，不上报"——但 `design4-impl.md` 全文没有"预案"二字，没有表、没有注册表、没有执行器、没有入选纪律。

**核心决策**：

| # | 决策 | 理由 |
| --- | --- | --- |
| D1 | **加一档"预案"，判据换轴**：凡"信号 → 必须动作"的时间窗 < 一次模型调用的，一律代码直拦 | 严重性只覆盖"已发生"（死亡），时间覆盖"即将发生"（叫杀）；后者同样躲不开模型延迟 |
| D2 | **预案分两段**：① 起手定式（同步直发，**不要求持有者**）② 管理循环（按回合分支，**要求持有者**） | 起手要在**任何持流状态下**都能发（`mud.send` 不占行流）；管理需要读回合结果，必须持流 |
| D3 | **管理循环拿不到持有者就放弃**（起手照发） | 抢占 = 打断仲裁 = §9 禁止；此时危机处置者归当时持流者（子级有执行智能） |
| D4 | **释放阀门 = 结束标志（主） + 断线 + 步级超时（兜底）**；不设看门狗 | 战斗的开始/结束/胜/败/死都有明显标志；断线已由 link 层收束；`WaitOpts.timeoutMs` 结构上必填，复用竞速机即自动继承 |
| D5 | **步级超时的收束语义是"重新评估"，不是"失败"** | 读世界判断是否已退出战斗：已退出按结束处理，否则继续下一回合——避免把可续的战斗误判为失败 |
| D6 | **结束标志一个判据服务三件事**：结束预案 / 生成摘要 / 唤醒根（战后复盘） | 与 §3.3"结算即唤醒"同构，不新增通道 |
| D7 | **动作纪律对预案档改为"可续"**（反射档不变） | "天然无后果"是反射的判据；0ms 档需要"出招/喝药/逃"这类**有后果但可续**的动作；不可逆动作仍禁 |
| D8 | **战斗原文不进 T2，只有摘要进** | 与子 agent 同构（§7 账目）：预案持流期间 read 结果只由预案消费 |
| D9 | **预案权归 T2 编制**（安全时），第一期人工写种子 | 仍然只有一个意图主体：T2 编制与授权，意识层只执行 |

## 第 3 章 机制与契约

### 3.1 预案形态（复用流程形态 + 起手/结束两字段）

```ts
export interface Contingency {
  id: string
  description: string
  /** 起手：**同步纯函数**，返回要发的命令（null = 本轮不发）。
   *  禁止 await、禁止调模型——0ms 保证依赖它在任何 await 之前发出。 */
  opening(world: World, hit: DangerHit): string | null
  /** 管理循环：可选（只需起手的预案不写）。按回合推进；
   *  响应 signal；内部每次 read 必须给 timeoutMs（类型上必填）。 */
  manage?(ctx: ContingencyCtx): Promise<ContingencyOutcome>
  /** 附加结束标志（全局 END_MARKS 之外的本预案专属形态）。 */
  endMarks?: RegExp[]
}
```

与 `flows` 的**唯一差别**：flows 由持流者（模型）调用；预案由**意识层（代码）触发调用**（§5.2"流程对计划是词汇、没有执行权"对两者同时成立——预案也不持有目标）。

### 3.2 触发：danger 表扩两个字段

```ts
export interface DangerRule {
  re: RegExp
  why: string
  interrupt?: boolean
  wake?: boolean
  abortWait?: boolean
  latch?: string          // 由字面量 'combat' 泛化为 world 字段名（支持常驻型锚）
  contingency?: string    // 新增：命中即同步起手 + 尝试启动管理循环
}
```

**执行序**（`observe`，全部在原同步段内）：

```
1. world.reduce(line)
2. danger.match(line)
   ├ contingency → ① const cmd = plan.opening(world, hit); if (cmd !== null) mud.send(cmd)   // 0ms，最优先
   │               ② void runContingency(id, hit)                                            // 异步启动（内部争持有者）
   ├ interrupt   → mud.send('halt')
   ├ wake        → onDanger(hit)      // wake 层 steer
   └ abortWait   → mud.abortWait(line)
3. REFLEX 匹配（吞触发行、留应答）
4. onActivity()（静默重锚）
```

**装配期护栏（互斥）**：同一条规则**不得同时声明 `interrupt` 与 `contingency`** —— `halt` 会打断自己刚发出的起手。检测到即装配期报错。

### 3.3 持有者与释放阀门

**持有者获取**：

```
runContingency(id, hit):
  if (mud.currentHolder !== null)      // 子级在途 / 根在途
     记 log「起手已发，管理循环放弃（行流被 <holder> 持有）」
     return                            // D3：不抢占
  holder = 'contingency'               // Holder 联合类型新增一支
  try { 管理循环 } finally { 释放持有者 }
```

**管理循环**：

```
for (round = 1; ; round++):
  r = await mud.read({
        holder: 'contingency',
        until: [...END_MARKS, ...plan.endMarks],
        quietMs: TURN_QUIET_MS,        // 回合级：本回合输出已到齐
        timeoutMs: STEP_TIMEOUT_MS,    // 步级兜底：重新评估（D5）
        signal,                        // 释放阀门
      })
  switch (r.reason):
    'done' | 'disconnected'  → 摘要 → wake.settle(摘要) → return      // D6
    'quiet' | 'timeout'      → world.inCombat === false ? 按结束处理
                             : round >= MAX_ROUNDS     ? 摘要(达上限) → wake.settle → return
                             : continue                                 // 继续下一回合
    'signal'                 → return                                   // 释放
    'danger'                 → 交 danger 表（可能起手已由 observe 发出）
  下一回合动作 ← plan.manage(ctx)   // 纯代码读 world 决定（可返回 null = 不发）
```

**三层释放（D4）**：

| 层 | 触发 | 状态 |
| --- | --- | --- |
| 主判据 | 结束标志（胜/败/死/战斗结束）命中 `until`，或 `world.inCombat` 翻转为 `false` | 已具备（world 的战斗 reducer 已双向覆盖开战/结束帧） |
| 兜底 1 | 断线：link 层 `onClose` → `finish('disconnected')` → 持有者立即释放 | **已实现**，无需新增（impl §3.1） |
| 兜底 2 | 步级 `timeoutMs`（`WaitOpts` 结构上必填） | **已实现**，复用竞速机即继承 |

> **关于"迟迟不释放多半是断线"**：同意，且比这更强——断线由 link 层收束，不需要预案自己检测。**保留超时的唯一理由是"半开连接"**（服务端进程死亡或网络路径静默中断，本地 socket 既无 FIN/RST、写也不报错），此时 `onClose` 不触发，只有超时能救。另外"结束标志形态未被语料覆盖"同样只有超时能兜。⇒ 标志是主判据、超时是防御性兜底，**两者都不可省**；但**都不需要新机制**。

**不设**：预案看门狗、预案总时长硬上限（各步超时之和已给出上界）、在途预案数量上限。若日后需要"整场预算"，复用 §4.4 子 agent 预算的同一 Config 语义（同源概念，不新造）。

### 3.4 与既有层的关系

| 关系 | 口径 |
| --- | --- |
| 与**反射档** | 反射纪律不变（天然无后果 + 吞触发行）；预案触发行**不吞**（进模型面与语料，并作为现场进摘要）——与意识层"无输出特例"一致 |
| 与**危险 latch** | 同一场战斗一条 latch（`world.inCombat` 边沿）；latch 泛化为字段名后，常驻型规则也可自带锚 |
| 与**静默唤醒** | 预案持流时 `idle()` 为 false ⇒ 静默唤醒被挡，战斗期不被打扰（现有行为，无需改） |
| 与**子 agent** | 子级在途时叫杀：**起手照发**（直发不占行流），管理循环放弃；子级的 `read` 会以 `reason:'danger'` 收束并携现场（现有行为） |
| 与 **T2** | T2 只在战后收到一次摘要（含结果/耗时/HP 变化/触发行/预案 id）；战斗期不遥控 |
| 与**技能** | 技能 = 给模型看的战术知识（安全时用）；预案 = 给代码执行的定式（战斗中用）。同一份战术知识的**两种承载，服务两个时间预算**；第一期预案人工写，`技能 → 预案` 的沉淀路径留第二期 |

## 第 5 章 实施切片与验收

**切片顺序**（每片自带会红的用例）：

1. **P1.1 表结构与起手**：`latch` 泛化 + `contingency` 字段 + `observe` 起手（同步）+ `Holder` 新增一支。**不含**管理循环。
2. **P1.2 管理循环与释放**：`run.ts` + 三层释放 + 摘要 + `wake.settle`。
3. **P1.3 战斗抓取扩充**：死亡写 `inCombat=false`、敌方 HP / 命中。
4. **P1.4 装配期护栏与 persona**：互斥自检（`interrupt` × `contingency`）、禁发表、措辞。

**验收断言**：

| # | 断言 | 口径 |
| --- | --- | --- |
| V1 | **起手时延** | 语料回放"叫杀"行 → 在**同一批次同步段内**已 `mud.send(起手)`；断言"行到达 → send"间隔 < 50ms，且该路径 **0 次模型调用** |
| V2 | **三种结束标志** | 胜 / 败 / 死 各一例 → 持有者释放 + **恰好一次** `wake.settle` + 摘要含结果 |
| V3 | **断线** | 连接关闭 → `disconnected` 收束 + 释放 + 摘要标明断线 |
| V4 | **半开连接** | 无结束标志、无 close、无新行 → `timeout` 收束 → 重新评估 → 最终释放（**不得**永久占用行流） |
| V5 | **不抢占** | 子级持流时叫杀 → 起手已发、管理循环放弃并记 log、子级 `read` 以 `danger` 收束（现有行为不变） |
| V6 | **互斥护栏** | 同规则同时声明 `interrupt` + `contingency` → 装配期报错（会红的用例） |
| V7 | **静默不打扰** | 预案持流期间静默 timer 到期 → 不唤醒（`idle()` 为 false） |
| V8 | **token 账目** | 一场战斗全程 → T2 收到 **1 次**摘要（非每回合）；无额外模型调用 |
