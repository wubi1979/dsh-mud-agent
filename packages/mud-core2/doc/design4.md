# mud-core 设计：自主玩家 · 五层心智

- 状态：**设计基线（2026-09-24；2026-09-25 修订：静态遮蔽替代动态权限、派单走宿主原生 subagent 工具、砍结算消化守卫）**，待实施
- 本文只描述目标架构，不记录演进过程

---

## 1. 第一原则与设计顺序

**以"自主玩家"为模型，以 token 预算为第一约束。**

两条推论：

1. **agent 的价值在于类人的灵活与自主**，架构的责任是保护它，而不是把 agent 编制成机器——若要用程序结构替换它的判断，就不必引入 agent；
2. **T2 闭环先于一切机制**。已实证：入站信息驱动 + 静默到期唤醒 + 大模型 = 完整自主行为（自己取钱、买食物、去茶室喝水、看地图找路），唯一卡点是 token 成本。因此 T2 路径是被证明存在的主干，设计要给它一个省 token 的组织形式，而不是替它玩。

设计顺序由此确定：**干 = T2 闭环自身**——三个唤醒源、唤醒上下文、计划编制、单子 agent 串行执行、结算回注、检视；技能沉淀、教训库、反射表、模型降档全部后置为**支**。子 agent 是主干的执行半边，不是支。

## 2. 五层心智模型

| 层 | 定义 | 类人对应 | 成本 | 纪律 |
|---|---|---|---|---|
| **存在** | MUD 信息联通：连接生命周期、行流、世界状态维护 | 神经系统的物理在场 | 0 | 世界状态是唯一真相，所有层读同一份 |
| **反射** | 命令直发：save、翻页、协议应答——刺激→动作，不问为什么、不管后果 | 膝跳反射——不经觉察 | 0 | 只放**天然无后果**的机械反应；需要"知道为什么"的动作归意识层 |
| **意识** | 持续感知（世界抓取、危险觉察）+ 条件触发：觉察到危险 → 中断当前活动 + 唤醒；子 agent 上报 → 唤醒 T2 | 持续知觉与条件反应——看到车冲过来猛地停下（知道为什么停） | 0 | **必须薄**：只感知与触发，不解释 |
| **思考** | T2：接收信息 → 目标 → 计划 → 检视 → 学习 | 前额叶——意图与 deliberation | 每次唤醒一次调用 | 唯一持有目标与意图连贯性的层 |
| **记忆** | 经验教训 | 海马沉淀 | 注入成本 | 三分：工作 / 陈述 / 程序（§6） |

```
                 ┌─────────────────────────────┐
                 │ T2 思考层（低频、贵、意图连贯）     │
                 │ 接收信息→目标→计划→检视→学习       │
                 └──────┬───────────────┬─────┘
                 计划下发│           ↑报告/上报/危险唤醒
                 ┌──────▼───────────────┐
                 │ 子 agent（无意图执行者）   │
                 │ 无目标智能·有执行智能      │
                 │ 引用技能=程序记忆          │
                 └──────┬───────────────┘
                        │发命令
    ┌───────────────────▼──────────────────┐
    │ 反射层：save/翻页直发（无觉察的机械反应）   │
    │ 意识层：世界抓取+危险觉察+条件触发（薄）    │←永续，向所有层供给状态
    │   觉察到危险 → 中断当前活动 + 唤醒          │
    │ 存在层：连接、行流、世界状态                │
    └──────────────────────────────────────┘
    记忆：工作（世界状态）/ 陈述（教训）/ 程序（技能）
          学习沉淀 ↑    唤醒/任务注入 ↓
```

## 3. T2 思考层：闭环与唤醒

### 3.1 闭环

```
唤醒 → 组装上下文 → 思考（消化结算报告 / 目标 / 计划 / 学习）
     → 下发计划（要点 + 边界声明 + 相关技能与教训）
     → 子 agent 串行执行（引用技能/流程）
     → 结算即唤醒，报告回注会话
     → T2 消化该次结算并检视在途计划 → 经验教训沉淀
```

### 3.2 三个唤醒源

| 唤醒源 | 对应人的注意力回归 | 条件 |
|---|---|---|
| 静默到期 | 主动环顾——"没事且没事干" | **且无行流持有者、且上次结算已消化**（子级在跑 = 有事在干，不打扰） |
| 意识层危险唤醒 | 惊吓 | 立即，不等静默期；用**高置信判据**（死亡 / 断线 / 攻击）。**去重挂世界状态**（如"正在战斗"），**不挂行模式**——行模式会在战斗每回合重新武装，导致每回合唤醒 |
| 子 agent 上报 | 下属汇报 | 受阻 / 完成 / 越界请示 / **异常终止（含预算耗尽）** |

- **源1 的守卫不能写成"无子 agent 在途"**：子 agent 目录里的空闲状态不代表任务完成（已结算的子级仍在目录里），据此判会让根在首次派单后永久认为"有事在干"；
- **双唤醒窗口**：子 agent 刚终结、结算唤醒还在排队时静默计时器恰好到期 → 根可能收到结算 + 静默两个唤醒。**无害，接受冗余唤醒**——T2 的决策输入是唤醒正文里的世界状态，不是唤醒次数；**不设"结算未消化"守卫**（为罕见冗余唤醒建状态子系统不值）。

**越界不设第四个唤醒源**：HP 缓降、进入战斗这类无行可警的世界越界由意识层抓进工作记忆，**在静默到期的唤醒摘要里呈现**——静默环顾本来就要带世界状态，越界事实搭这一次车。代价是"HP 开始跌"到"T2 知道"的延迟 = **静默期 ∪ 子级在途时长 ∪ 根阻塞期间**；遭攻击这类有行可警的场景仍走危险源立即唤醒。

### 3.3 结算即唤醒（检视是计划级），且唤醒是 best-effort

一步一请示是浪费——"异步"的确切含义是**要点级不打断**：计划执行中，子 agent 不为单个要点向 T2 请示，意外自行消化；只有受阻 / 完成 / 越界请示 / 异常终止四类结算才回到 T2。

**完成也唤醒**：子 agent 的结算通知会投递到父会话——父空闲则开新回合，父运行中则步边界插话，没有"只落日志、等自然醒"的第三态。因此：**结算即唤醒，检视是计划级的**——一次醒来消化该次结算并顺带检视在途计划。token 代价明码入账（§7：每份计划约 2 次 T2 调用 = 编制 + 结算检视）。

**但"唤醒"必须按 best-effort 理解**：宿主存在**四种不唤醒状态**，其中两种完全静默——① 子级首个 prompt 从未被接受；② 父不在注册表（丢弃且无日志）；③ 父正在关闭（转为持久但不唤醒的注入）；④ 投递抛错（仅记警告）。因此：

- **不承诺"必然送达"**；交付失败**无独立兜底机制**，由 §4.4 的预算路径承担（预算到期的"超时失败"本身就是一次结算，走同一通道回根）；
- 结算消息只含子级的**非空文本块**（无结构化输出通道），父要细节只能靠子级主动上报；书写格式用**固定文本约定**（结果 / 问题 / 本次新教训），供根 T2 读文本消化——**不做代码解析**；
- 父运行中收到的结算**不丢失**，它在下一个步边界被消费（根阻塞在问人时会推迟到问人返回之后）。

### 3.4 唤醒上下文组装

每次唤醒的正文 = 身份 + 世界状态摘要 + 相关教训。**计划与报告不需要组装器搬运**——它们是会话历史（计划消息 + 结算报告），由宿主每请求自动携带；组装器**只补模型看不到的东西**。

**但"历史全量携带"在缺省组合下不成立**：缺省挂了 compaction，它在每个步前自动运行并按预算**重写会话面**（工具结果超阈值会被裁剪）。⇒ **"计划被压缩后重注"是必需项**，不是可选项；不挂 compaction 的部署自然无此问题。

组装遵循克制原则：只给 T2 本次决策需要的；唤醒原因是**事实**（"HP 18%"），不是指令（"请逃跑"）。

## 4. 子 agent：无意图执行者

### 4.1 定义（五条）

1. **无目标智能**：不生成目标、不质疑意图——它的会话里没有"要不要"的问题，只有"怎么完成"；
2. **有执行智能**：保留解决问题的能力（走错路会看地图）。执行细节全权：前提不成立的步骤跳过、执行意外自行处置；
3. **无意图**：不订阅世界状态，不主动发现任何需求（口渴饥饿是 T2 需要知道并规划的事）；生命周期 = 任务生命周期：接到要点 → 执行 → 报告 → 消亡，无常驻、无自主唤醒。**"无意图"只描述它不生成目标，不描述它少思考——"有执行智能"必须完整保留**；
4. **一个计划一个子 agent**：计划可含 N 条要点，由同一个子 agent **串行**执行（任务并行在单连接的 MUD 中意义不大）；要点级拆分作为后置优化；
5. **无跨计划记忆**：它不需要知道上个计划是否成功、也不需要知道为什么要执行 ⇒ 一计划一新子级；其上下文只随当前计划增长，**上界由 §4.4 的预算给出**（不另设历史管理）。由此：冷恢复续跑基本可砍，只保留"问人后带答案重入当前计划"。

### 4.2 形态

用宿主原生子 agent（独立会话、隔离、结果回注）——独立会话天然实现"无目标"：它看不到主体的历史包袱，世界里只有任务；隔离同时是安全。同会话执行模式做不到这一点。**派单走宿主原生 `subagent` 工具**（provider=spawn、continuable），T2 直接调用，prompt = 任务要点 + 边界声明 + 相关技能与战术教训正文（T2 用 `skill` 工具自取拼接）；插件不自建派单通道。

上下文组装：任务要点 + 边界声明 + 相关技能与战术教训 + **可自取的世界状态**——**不含全量历史**。"知道自己在做什么" = 任务上下文 + 执行中的即时感知；精确状态由子级用 `mud_state` 自取，不靠组装器搬运。

### 4.3 权限与边界

- **静态遮蔽，不做动态权限**：子 agent 会话在 `mud_send` 工具内按一张**静态禁发表**拦截肯定用不到的不可逆命令（自杀 / quit / drop all 类），根会话不受限。计划边界**不进权限系统**——经济类动作（买/卖）不被拦（"取钱/买食物"验收依赖它），靠执行智能与 persona 纪律，**无例证不加机制**；
- 禁发表入选纪律：只收**天然不可逆且任何计划都不该需要**的命令；新例证（语料审计发现）→ 加一行表，不为推测隐患建机制；
- **人工交互只在根会话**：宿主规定被父拥有的子 agent 问人会被直接拒绝——子 agent 遇到必须问人的事，把问题装进结果上浮，由根问人兜底（§5.3）；
- **紧急处置权**：仅限可逆的即时动作（逃跑 / 停手 / 喝药），不上报；不可逆动作（交易、丢弃、交任务）**不在子 agent 权内**——身体可以本能躲闪，不会本能地买卖贵重物品；
- 处置不了 / 没见过的危险 → 中断执行，携现场上报 T2（目标级重规划）。

### 4.4 预算与释放

- **总体预算，耗尽即失败上报**：给每个子 agent 一份预算（Config 缺省）；**派单后（`agent/created`）登记截止时刻**，到期 → `interrupt_agent`，报告**只走宿主结算路径**（interrupt → 子级到静止态 → 宿主投递结算，单一报告，插件不自报以免双结算）。**不设**子级看门狗、**不设**在途子级上限；
- **不得用"列出子 agent"来判定**：其状态字段不代表任务完成；
- **释放阀门是协作式的，必须自持**：宿主**没有**任何子 agent 超时；激活槽只在"启动失败回滚"与"激活终结"两处释放，而"中断"只停当前回合、**不释放槽**——只有当被中止的等待能到达静止态，才会触发结算并回收槽。⇒ **`wait()` 必须 ①响应 `exec.signal` ②自带超时**（绝不无界等待）。这与宿主工具超时同属"协作式、绝不硬杀"的契约：生命周期归宿主，可中止性归工具作者；
- **行流持有者是进程级的**（单 MUD 连接唯一）：同一时刻最多一个持有者（根或某个子级），冲突时 fail loud——根与子级都持有全套工具，并发读会各拿半截行。

### 4.5 工具可见面

- **`agent/created` 的监听器必须注册在宿主（未限定作用域）或 preset 作用域**：父 agent 与子 agent 的作用域是**兄弟**（都挂在 preset standing key 上），注册在**父 agent 自己作用域**的监听器**看不到自己的子级**；
- 装配期自检：**已创建子 agent 的可见面必须包含 `mud_send`/`mud_flow`/`mud_state`**；
- **子级在途时 **T2 不得直接调 `mud_send`**（应走 `send_message`/`interrupt_agent`）；纪律写进 persona，并由 §4.4 的进程级持有者检查给牙齿。

## 5. 执行

### 5.1 工具面（mud 工具面；宿主原生 `subagent`/`send_message`/`interrupt_agent` 另见 §4.2/§4.5）

```ts
mud_send({ cmd?, listen?, timeoutMs? })   // 无 cmd = 裸读；有 cmd = 发后读一段
mud_flow({ id, answer? })                  // 凭据/标准流程调用
mud_state()                                // 世界状态快照
```

工具结果**原文返回**（过程即结果，模型看原文自决）；超时必须显式给出或由工具注入缺省——宿主没有默认超时。

### 5.2 流程：凭据型用代码，知识型用技能

- **凭据 / 不可逆型**（login、fullme、买卖类操作）：**代码流程**，一个异步函数，对模型只暴露 `mud_flow({id})`——密码与验证码在发送瞬间插值，不进任何模型上下文；
- **知识型**（怎么练功、怎么走地图、NPC 套路）：**技能文本**，宿主原生加载与热更，模型照着做、意外自己处理。

流程对计划是**词汇，不是平行执行者**：编制时引用、执行时调用，没有执行权。

### 5.3 需要人时的链路

**问题随结果上浮，问人只在根。** 子 agent 遇到必须问人的事，以"未完成 + 问题"结束 → 问题随结算上浮 → **根会话**问人取码 → 带答案**重入当前计划**（优先）。

**第一期不注册图片识别工具**（必然失败的桩会让模型先反复调用它、白烧请求）；fullme 直接走上面这条真实路径。识别工具未来接通时只换实现，链路与验收路径都不变。

### 5.4 计划里的无关内容：不做净化机制

计划是**意图快照，不是合同**。人拿到的计划总有废话，人从不卡在"这条好像没必要"上——执行智能消化：前提不成立的步骤跳过，走到半路失效就改。步骤级自决、目标级上报。要改的是计划编制的质量（提示词与示例），**不是为模型的平庸输出设计防御机制**。

### 5.5 反射与意识的分界

分水岭是**"知道为什么"**：不需要知道为什么、后果也不管的动作放反射层（save、翻页——天然无后果，多发无害）；需要"知道为什么"的动作归意识层（如觉察到危险要中断当前活动）。

细则：

- **反射动作吞掉触发它的那一行**（提示文本对模型零信息量），但**保留命令的应答**（"存档失败"这类负面结果不能被静默吞掉）；语料与日志始终保留全部行；
- 意识层的动作**无输出特例**：照常进模型面、照常参与判据——它的必要性由输出自身揭示（需要的给信息、不需要的给无害噪声）。

误判后果：若把"要中断当前活动"这类判断放进反射层，就得写成"行文特征 → 命令"的映射表——危险形态每多一种就改一次表，且无法解释为什么发。

### 5.6 紧急响应：三级，单向升级

| 层级 | 场景 | 机制 |
|---|---|---|
| **意识**（0ms） | 遭袭 / 叫杀的第一反应 | 中断当前活动，使角色能接受后续指令（逃/战）；只中断不定向，去向由预案或 T2 决定；觉察后视判据级别同时唤醒 T2 |
| **子 agent**（执行智能） | 计划内的常见意外、可逆即时处置 | 预案动作，不上报；处置不了携现场上报 |
| **T2**（重规划） | 目标级变化、没见过的危险 | 携现场唤醒 |
| **硬底线** | 死亡 / 断线 / 凭据 | 意识层代码直接拦截，不依赖任何模型 |

**不存在"打断仲裁"**：没有两个执行者争控制权，只有单向的"处置不了就升级"。

**"中断当前活动"的具体用法暂不设计**：它本质是流程性、防御性的操作（切换活动前先中断手里的活），等真实场景需要区分对待时再补规则。当前只需知道一点：它会中止正在进行的活动、是有后果的动作，因此不许对有收益的活动主动发。

## 6. 记忆三分与学习回路

| 类型 | 内容 | 技术承载 | 注入点 |
|---|---|---|---|
| **工作记忆** | 世界当前状态（HP / 口渴 / 位置 / 登录态 / 金钱） | 世界状态（意识层维护） | 所有层读同一份 |
| **陈述记忆** | 经验教训（"那个店周三不开门"、"死后先捡尸体"） | 教训库（上限条数，超限由 T2 归纳合并——人会遗忘，记忆会压缩） | 战略教训 → T2 唤醒上下文；战术教训 → **拼进子 agent 任务描述** |
| **程序记忆** | 技能与流程（"去茶室的走法"、login） | 技能目录（人写种子 + 模型沉淀） | 计划编制引用、子 agent 执行调用 |

学习因此有双产物：**教训**（陈述，来自检视失败与意外）+ **技能**（程序，来自检视成功的要点沉淀）。

三条落地约束：

- **子级必须先能读到，才谈得上积累**：宿主只把技能**目录概要**注入根会话，子级看不到卷宗——相关技能/教训正文要**由根拼进子级任务描述**（没有"把某技能注入某子 agent"的专用接口）；
- **教训回库第一期用文本约定**：子级结算末尾固定一节"本次新学到的教训"，据此决定是否沉淀（宿主没有结构化输出通道）；
- 因此成本**随记忆积累下降**（不是"单调下降"）——前提是回库链路已通，否则每个子级都从零学起。

**技能沉淀的前置四条（装配期自检，否则静默失效）**：① 组合里真有技能工具（目录注入与根保留由它触发，子级本身不会触发）；② 沉淀走写/改工具（只有这两个工具名触发快速失效，其余依赖文件监听）；③ 会话有工作目录；④ 沉淀**低频批量**（每次目录变更都会在根历史追加一整份新目录副本，旧副本不被替换）。

## 7. 成本账目

| 项 | 成本 | 说明 |
|---|---|---|
| 存在 / 反射 / 意识 | 0 | 代码 |
| T2 | 低频 × 单次贵 | 三源唤醒；**结算即唤醒**（§3.3）——要点级不请示，计划级必检视 |
| 子 agent | 每计划 1 次启动 + 若干次 × 上下文小 | **同模型下省的是上下文尺寸**：T2 上下文 = 全量历史 + 目标 + 计划（大），子级上下文 = 要点 + 状态 + 战术教训（小）。**结算唤醒 1 次/计划是固定成本**。模型降档（子级用便宜模型）只适用全新会话路线（继承历史的那条被固定为父模型以保缓存复用），二期实施 |
| 技能引用 | 0 | 已沉淀的要点执行近乎零思考 |

**上限主张按计划长度加条件**：主干含子 agent 后，"每步一次 T2 全量调用"变为"每计划一次编制 + 若干次小上下文子 agent + 1 次结算唤醒"——**长计划净省、短计划未必**（1–2 步的计划，子级冷启动 + 结算可能高于 T2 直跑）。因此：

- 上限主张**只对长计划成立**，须逐场景断言，恶化即回退；
- **短任务由 T2 直跑**（根持有全套工具，零额外开销）——这是正本清源的兜底，而不是"更小的子 agent"；
- 三条必须入账的事实：① 子级上下文是**额外支出**（自有系统提示 + 工具 schema + 历史），父在子级前台运行期间不重发自己的请求，但**每份结算在父空闲时开一个新回合**（N 次结算 = N 个回合）；② **续跑 ≠ 重跑**（前者重放整个子级历史且有多个失败先决条件，后者必得新 id、丢记忆）；③ 缺省挂 compaction，"历史全量携带"不成立；
- **验收必须量成本本身**：根上下文规模 / 每场景峰值 token（只数步数量的是正确性，不是成本）。

## 8. 开工前置与验收

**开工前必须先落的三项**（否则验收会翻车、或子级拿不到工具）：

1. **静态禁发表**：随 `mud_send` 工具落地，子会话生效（§4.3）；
2. **监听器作用域**：`agent/created` 注册在宿主或 preset 作用域，并加"子级可见 `mud_send`/`mud_flow`/`mud_state`"的装配期断言（§4.5）；
3. **成本指标**：验收必须同时量 token 成本（见下）。

**干的落地顺序**：入站链与等待原语（响应中止信号 + 自带超时）→ 语料回放用例（完成句跨批 / 危险中断等待 / 同批移交 / 判据失配记错）→ 意识层与世界抓取 → 唤醒与上下文组装 → 计划编制与单子 agent 串行执行 → 结算回注与计划级检视 → 静态禁发表与预算 → fullme 链路 → 观测与验收全表。

**验收**：

- **行为**：已实证的四行为（取钱 / 买食物 / 喝水 / 找路）在新账目下复现；**四行为必须至少一次走"计划 → 子 agent → 结算"全链路**；
- **正确性计数**：**决策点数 = 步开始事件数**（等价于"空续步 = 0"红线）；**实际调用数单独计**，两者之差即重试/失败；
- **成本计数**：**根上下文规模 / 每场景峰值 token 不劣于实证基线**；
- **全链路**：fullme 单列——问题上浮 → 根问人 → **重入当前计划**，断言全程无子 agent 侧问人；
- **释放**：子级超预算 ⇒ 根必被唤醒**且激活槽被释放**；根与子级并发读必须被拒；
- **静态遮蔽**：子会话发自杀 / quit 类命令被拒、根会话放行；经济类越权靠语料审计兜底（无机制）；
- **压缩守护**：无例证不建；若实测出现计划被压缩致失忆，先试部署层关 compaction。

**支（按需生长，顺序不预设）**：技能沉淀自动化 → 教训库与归纳 → 反射表 → 子 agent 模型降档 → 要点级拆分与编排 → 维持类行为的更省路径。

**护栏**：任何支的引入以 token 账目恶化为否决条件；关掉任何支，系统退化为干（主干不依赖支存在）。

## 9. 边界：什么不做

- **不自建 agent loop**：唤醒、回合、上下文组装、人工交互、凭据、持久化、无密钥回放全部用宿主原生；
- **不做打断仲裁**：无优先级比大小、无准入判定、无流程复位、无残余队列清除——没有两个执行者，就不需要仲裁；
- **不做净化机制**：不替模型修剪计划里的废话，不建 plan 存储与进度状态机；
- **不自建子 agent 历史管理**：一计划一子级、无跨计划记忆，上界由预算给出；
- **不做动态权限**：只有一张子级静态禁发表（工具内一行判断），计划边界不进权限系统；
- **不自建派单/结算通道**：派单走宿主原生 `subagent` 工具，结算投递与激活槽归宿主；
- **不做超时/看门狗子系统**：只有一个预算与一个协作式释放阀门；
- **不注册实现不了的桩工具**：必然失败的工具会教模型怀疑工具面。
- **不为无例证/宿主的事实设计机制**：基于推测且无作者证实的设计就是冗余设计。

## 10. 一句话总结

**以"自主玩家"为模型、token 为第一约束：存在（联通）、反射（直发）、意识（薄规则）、思考（T2 目标-计划-检视-学习）、记忆（三分）五层心智；T2 由静默 / 危险 / 上报三源唤醒（唤醒是 best-effort，危险去重挂世界状态），结算即唤醒、检视为计划级；无意图但有执行智能的子 agent 串行执行计划要点（一计划一子级、无跨计划记忆、总预算给出上界、耗尽即失败上报），流程资源化为技能与代码两类，紧急三级响应、单向升级、无仲裁——不做两套系统的解法，是让每个机制长在 T2 主干该在的位置上。**
